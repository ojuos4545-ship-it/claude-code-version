# CLAUDE.md 작성법, 초보자도 /init으로 쉽게 만들기

> 💡 **한 줄 요약:** CLAUDE.md 작성법은 생각보다 간단합니다. `/init`을 입력해 초안을 받고, 필요 없는 줄을 지운 뒤, 내가 자주 하는 말 몇 줄만 적으면 끝이에요.

[IMAGE: 썸네일 | 설명: 정방형 비율, CLAUDE.md 작성법의 흐름(/init으로 초안 만들기, 줄 지우며 다듬기, 새로 열어 확인)을 세 칸으로 나열한 대표 이미지]

안녕하세요, 여러분! "어제 알려 준 걸 오늘 또 설명해야 하나?" 싶으셨다면 CLAUDE.md 작성법을 알아 두실 때입니다.
어려운 코딩 지식 없이도 `/init`이라는 명령 하나로 첫 파일을 만들 수 있어요.
이 글을 따라오시면 파일이 무엇인지, 어디에 두는지, 무엇을 적는지까지 직접 해 보실 수 있습니다.

앞선 글 '클로드 코드 핵심 기능 5가지, 처음 쓰는 분이 먼저 익힐 것'에서 첫째로 소개한 기능의 실습편이에요.
앞 글을 안 보셨어도 괜찮으니 편하게 읽어 주세요.

## 🛠️ 시작하기 전에 준비할 것들

* **준비물:** `claude`를 한 번이라도 실행해 본 컴퓨터, 연습용 폴더 하나
* **소요 시간:** 초안은 `/init`이 금방 만들어 줍니다. 시간은 다듬는 데 쓰게 돼요.
* **난이도:** 입문. 코딩 실력보다 "내가 매번 하는 말이 뭐였지?"를 떠올리는 일이 더 중요합니다.

처음 나오는 말을 먼저 풀어 드릴게요.

| 말 | 쉬운 뜻 |
| :-- | :-- |
| CLAUDE.md | Claude에게 보여 주는 메모 파일. `.md`는 글자만 담는 간단한 문서 파일이라는 뜻이에요 |
| `/init` | 이 메모 파일의 초안을 대신 만들어 주는 명령 |
| 세션 | `claude`를 켜서 끌 때까지의 대화 한 번 |

이 글의 기능 설명과 권장 수치는 **조사일(2026-10-27)에 연 공식 문서 기준**입니다.
클로드 코드는 업데이트가 잦으니 `claude --version`으로 버전을 확인하고, 글 아래의 공식 문서와 함께 봐 주세요.

글 중간의 '직접 해 본 결과'는 같은 날 Claude Code 2.1.311 버전으로, 파일 세 개짜리 연습용 할 일 목록 프로젝트에서 돌려 본 기록입니다.
질문을 한 번 보내고 답을 바로 받아 오는 방식(`claude -p`)을 썼어요.
AI는 같은 질문에도 답이 조금씩 달라질 수 있으니, 여러분 화면에서는 결과가 다를 수 있습니다.

## 1. CLAUDE.md가 뭐예요? - 왜 만들어 두면 좋을까요?

Claude는 대화를 새로 시작하면 어제 한 이야기를 기억하지 못합니다.
그래서 어제 알려 준 규칙을 오늘 또 말해야 하는 일이 생기죠.

비유하자면 매일 첫 출근하는 신입 직원과 같습니다.
어제 일을 기억하지 못하니, 책상에 인수인계 메모를 붙여 두는 거예요.
그 메모가 **CLAUDE.md**입니다. (공식 문서의 비유가 아니라 이해를 돕기 위한 제 설명입니다.)

[IMAGE: 다이어그램 | 설명: CLAUDE.md 작성법의 출발점. 새 대화는 어제를 기억하지 못하지만, CLAUDE.md를 시작할 때 읽고 나면 메모 내용을 알고 시작한다는 3단계 흐름도]

그렇다면 언제 메모 한 줄을 적으면 될까요? 공식 문서가 드는 기준은 이런 때예요.

* Claude가 같은 실수를 두 번째로 할 때
* 지난번과 똑같은 설명을 또 입력하게 될 때
* 함께 일하는 사람도 같은 설명이 필요할 때

쓰기 전과 후는 이렇게 달라집니다. 특정인의 후기가 아니라 흔한 상황을 일반화한 표예요.

| 상황 | 쓰기 전 | 쓰기 후 |
| :-- | :-- | :-- |
| 확인하는 방법 | 대화를 열 때마다 "이렇게 확인해"를 입력 | 파일에 한 줄 적어 두면 다음 대화부터 알고 시작 |
| 같은 부탁 | 지난번과 같은 부탁을 또 입력 | 한 번 적어 두고 읽은 채로 시작 |

실제로 비교해 봤습니다.
같은 연습 프로젝트를 둘로 복사해, 한쪽에만 아래 9줄짜리 CLAUDE.md를 두었어요.

```markdown
# 프로젝트
- 개인 연습용 할 일 목록 웹페이지 (HTML, CSS, JavaScript만 사용)

# 실행·확인
- 미리보기: `python3 -m http.server 8000` 실행 후 브라우저에서 localhost:8000 열기
- 코드를 바꾼 뒤에는 위 방법으로 화면이 열리는지 확인했다고 알려 줘

# 규칙
- 설명과 답변은 한국어로, 결론부터 말해 줘
- 새 라이브러리는 설치하기 전에 먼저 물어봐
- 들여쓰기는 2칸
```

그리고 두 쪽에 똑같이 물었습니다.
"이 페이지를 고친 뒤에 화면이 잘 열리는지 확인하려면 어떻게 해야 해? 방법만 알려 줘."

| | CLAUDE.md 없음 | CLAUDE.md 있음 |
| :-- | :-- | :-- |
| 답의 모양 | 확인 방법 5가지를 나열 | 명령어 하나로 4단계 안내 |
| 내용 | 일반적인 방법들 (프로젝트와 상관없는 내용도 섞임) | 파일에 적어 둔 방법 그대로 |
| 첫 문장 | "확인하는 방법은 다음과 같습니다" | 실행할 명령부터 (결론 먼저) |

파일에 한 줄 적어 둔 것만으로 답이 '일반적인 정답 목록'에서 '이 프로젝트의 정답 하나'로 좁혀졌어요.
다만 한 번 돌려 본 결과이고, 같은 질문도 문장은 매번 조금씩 달라집니다.

참고로 이 파일은 지시서가 아니라 **참고 자료**에 가깝습니다.
공식 문서에 따르면 엄격한 준수가 보장되지는 않아요.

## 2. 어디에, 어떻게 만들까요? - /init으로 따라 하기

파일을 둘 곳은 **프로젝트 폴더의 맨 위**, 한 곳이면 충분합니다.
이름은 `CLAUDE.md`로 정확히 써야 해요.

[IMAGE: 포인트카드 | 설명: CLAUDE.md 작성법 중 파일 위치 카드. 처음에는 프로젝트 폴더 맨 위의 CLAUDE.md 한 곳이면 충분하고, 나중에 모든 프로젝트용 ~/.claude/CLAUDE.md와 나만 쓰는 CLAUDE.local.md를 쓸 수 있다는 정리]

나중에 필요해지면 두 곳을 더 쓸 수 있어요.
내 컴퓨터의 모든 프로젝트에 적용되는 `~/.claude/CLAUDE.md`(`~`는 내 홈 폴더)와, 프로젝트 안에서 나만 쓰는 `CLAUDE.local.md`입니다.
처음에는 **프로젝트용 하나**로 시작하시길 권해요.

이제 직접 만들어 볼까요? 아래 순서대로 차근차근 따라와 주세요.

1. **프로젝트 폴더에서 `claude` 실행:** 연습용 폴더로 이동해서 실행하세요. (파일이 만들어질 폴더이니 폴더를 잘못 고르지 않았는지 먼저 확인합니다.)
2. **`/init` 입력:** Claude가 폴더 안의 코드를 살펴보고 초안을 만들어 줍니다. (이미 CLAUDE.md가 있으면 덮어쓰지 않고 개선안을 내놓아요.)
3. **만들어진 파일 읽어 보기:** `/memory`를 입력하면 목록이 나오고, 고르면 편집기로 열립니다.
4. **줄이기:** 코드를 열면 바로 아는 줄은 지우고, 막연한 줄은 구체적으로 바꿉니다. (이 단계가 가장 중요해요.)
5. **확인하기:** `claude`를 껐다 다시 켜고 `/context`를 입력해 파일이 올라와 있는지 봅니다.

[IMAGE: 다이어그램 | 설명: CLAUDE.md 작성법 5단계 흐름도. claude 실행, /init으로 초안 받기, 파일 열어 읽기, 줄이기, 새로 켜서 /context로 확인하는 순서]

연습 프로젝트(아직 CLAUDE.md가 없는 상태)에서 `/init`을 실행해 보니, 15초 남짓 만에 17줄짜리 파일이 만들어졌습니다.
빌드나 테스트 도구가 없다는 안내, 파일별 설명, 그리고 지금은 쓰지 않는 `old/` 폴더는 건드리지 말라는 메모가 들어 있었어요.

눈에 띈 점은 세 가지였습니다.

* **언어:** 화면 문구는 한국어인데 초안은 영어로 쓰여 있었어요. 한국어로 바꿀지 정하는 것도 다듬기의 일부예요.
* **지울 후보:** 파일별 설명은 코드를 열면 바로 아는 내용이라 지울 후보였습니다.
* **남길 후보:** "`index.html`과 `app.js`가 같은 이름(id)을 쓰니 한쪽을 바꾸면 양쪽을 고쳐라"는 경고는 놓치기 쉬운 함정이라 남길 후보였어요.

이 기준대로 줄이고 한국어로 바꾸니 7줄이 되었습니다.

```markdown
# 프로젝트
- 연습용 할 일 목록 웹페이지 (HTML, CSS, JavaScript만 사용)
- 확인: index.html을 브라우저로 열기 (빌드·테스트 도구 없음)

# 주의
- index.html의 id(`task`, `add`, `list`)는 app.js와 짝이라, 바꾸면 두 파일을 함께 고친다
- `old/`는 쓰지 않는 예전 연습 코드라 건드리지 않는다
```

5단계의 `/context`도 실행해 봤습니다. 아래처럼 방금 만든 파일이 목록에 올라와 있었어요. (필요한 부분만 옮겼습니다.)

```text
Memory files   369 tokens   0.0%

Type      Path                          Tokens
Project   .../todo-practice/CLAUDE.md   369
```

목록에 파일이 보이면 Claude가 읽고 있다는 뜻입니다.
옆의 숫자(토큰)는 AI가 읽는 분량이라고만 알아 두세요. 17줄 초안은 369, 7줄로 줄인 파일은 180이 나왔어요.
같은 내용을 담고도 읽는 분량이 절반 정도로 줄어든 셈입니다.

> 📌 **전문가 Tip:** 공식 모범 사례는 `/init`이 시작 버전을 만들어 줄 뿐이고, 거기서부터의 일은 주로 줄을 지우는 것이라고 설명합니다. 초안이 허전해 보여도 채우려 하기보다 덜어 내는 쪽에 시간을 써 보세요.

## 3. 무엇을 쓰고 무엇은 뺄까요? - 좋은 예와 나쁜 예

CLAUDE.md 작성법에서 가장 자주 막히는 곳이 바로 여기예요.
공식 모범 사례가 말하는 **적을 것**은 이렇습니다.

* 일이 끝났는지 확인하는 방법 (실행하는 명령 등)
* 코드만 봐서는 헷갈리기 쉬운 곳
* 파일 안에는 남아 있지 않은 나만의 약속
* 두 번 이상 고쳐 말한 것

**뺄 것**을 가려내는 질문은 딱 두 개입니다.
"코드를 읽으면 알 수 있나?" 그리고 "Claude가 실제로 찾아볼까?"예요. 둘 다 "예"라면 지우셔도 됩니다.

막연한 말보다 확인할 수 있는 말이 좋다는 점은 이런 비교로 확인됩니다.

| 나쁜 예 | 좋은 예 | 이유 |
| :-- | :-- | :-- |
| 코드를 깔끔하게 써 | 들여쓰기는 2칸 | 기준이 눈에 보여야 확인할 수 있음 |
| 바꾼 것을 테스트해 | 커밋 전에 `npm test` 실행 | 어떤 명령을 쓰는지가 담김 |
| 프로젝트 구조는 이렇다 (폴더 수십 개 나열) | `src/legacy/`는 쓰이지만 새 코드는 그 방식을 따라 하지 않는다 | 읽으면 알 수 있는 것은 빼고 함정만 남김 |

표의 문구는 공식 문서의 예시를 한국어로 풀어 쓰거나 합친 것이라, 원문과 글자까지 똑같지는 않아요.

[IMAGE: 비교표 | 설명: CLAUDE.md 작성법의 나쁜 예와 좋은 예를 짝지은 비교표. 코드를 깔끔하게 써는 들여쓰기는 2칸으로, 바꾼 것을 테스트해는 커밋 전에 npm test 실행으로, 폴더 구조 나열은 src/legacy/ 함정 한 줄로 바꾼 모습]

이 차이도 직접 확인해 봤습니다.
연습 프로젝트에 "새로고침해도 할 일 목록이 남도록 저장 기능을 추가해 줘."라고 요청하고, CLAUDE.md의 규칙 한 줄만 다르게 뒀어요.

| 규칙 | 결과 (저장할 때 쓴 이름) |
| :-- | :-- |
| "데이터는 적절하게 저장해" | `todos` |
| "할 일 목록은 localStorage의 `todo-items` 키에 JSON 배열로 저장한다" | `todo-items` |

모호한 규칙이 무시된 건 아니에요.
기준이 없으니 Claude가 알아서 이름을 정했을 뿐이고, 구체적으로 적자 정해 둔 이름 그대로 쓰였습니다.
이름처럼 코드만 봐서는 알 수 없는 약속일수록 한 줄로 적어 둘 가치가 있어요.

[IMAGE: 포인트카드 | 설명: CLAUDE.md 작성법 판별 카드. 코드를 읽으면 알 수 있나, Claude가 실제로 찾아볼까 두 질문이 모두 예이면 뺀다. 적을 것은 확인 방법, 헷갈리기 쉬운 곳, 나만의 약속, 두 번 고쳐 말한 것]

> 📌 **전문가 Tip:** 비밀번호나 API 키(서비스 사용 열쇠)는 이 파일에 적지 않으시길 권합니다. 공식 문서에 직접 금지하는 문구가 있는 것은 아니지만, 이 파일은 팀과 공유될 수 있고 내용이 Claude에게 전달되기 때문에 안전상 그렇게 하는 편이 좋아요.

## 4. 안 지켜질 때는 어떻게 하나요? - 흔한 실수 3가지

쓰다 보면 "분명히 적었는데 왜 안 따르죠?" 하는 순간이 옵니다.
대부분은 아래 세 가지 중 하나예요.

**1) 너무 길어요**

조사일 기준 공식 문서는 파일당 200줄 미만을 목표로 짧게 유지하길 권장합니다.
길수록 지시를 놓칠 가능성이 커지기 때문이에요.
앞에서 본 것처럼 줄이는 일만으로도 읽는 분량이 절반으로 줄었습니다.

**2) 말이 막연해요**

"깔끔하게", "적절하게" 같은 말은 사람마다 기준이 달라요.
위의 저장 이름 비교처럼, 숫자나 이름이 들어간 구체적인 한 줄로 바꿔 보세요.

**3) 서로 반대되는 말이 있어요**

일부러 시험해 봤습니다.
메모 파일 두 개에 반대되는 말을 적었어요. 하나는 "답변은 한 줄로만 짧게 해", 다른 하나는 "항목별로 나눠서 자세하게 설명해"였습니다.
같은 질문을 세 번 했더니 결과가 이랬어요.

* 1회: 항목별로 나누되 각 항목은 짧게 쓰는 절충안으로 답하고, 어느 쪽을 따를지 되물었어요.
* 2회, 3회: 한 줄 답변을 따랐다고 밝혔습니다.

공식 문서 설명처럼 어느 쪽을 따를지 매번 달랐어요.
세 번 모두 충돌 사실을 스스로 알려 준 건 다행이지만, 항상 그럴 거라고 믿기는 어렵습니다.
이런 알림이 보이면 한쪽을 지우거나 하나로 합치는 게 가장 확실해요.

[IMAGE: 포인트카드 | 설명: CLAUDE.md 작성법에서 지시가 안 지켜질 때 점검할 세 가지 카드. 너무 길지 않은지, 막연한 말은 구체적으로, 서로 반대되는 말이 없는지]

그런데 CLAUDE.md는 어디까지나 '참고 자료'라서, 단 한 번도 어기면 안 되는 일까지 맡기기는 어렵습니다.
그런 경우에는 나중에 배우게 될 '훅'이라는 자동 실행 기능을 쓰는 것이 공식 문서의 안내예요.
지금 단계에서는 이름만 알아 두셔도 충분합니다.

## 5. 자주 묻는 질문 - 이런 건 어떨까요?

**Q. CLAUDE.md를 꼭 써야 하나요?**
안 써도 클로드 코드는 동작합니다.
같은 설명을 반복하거나 같은 부탁을 두 번 하게 될 때, 그때 한 줄 적어 두셔도 늦지 않아요.

**Q. 제대로 만들어졌는지 어떻게 알죠?**
`claude`를 새로 켜고 `/context`를 입력해 보세요.
목록에 CLAUDE.md가 보이면 성공입니다. 안 보인다면 파일이 프로젝트 폴더 맨 위에 있는지, 이름이 정확한지 확인해 주세요.

**Q. '자동 메모리'라는 것도 있던데 뭐가 다른가요?**
CLAUDE.md는 내가 직접 쓰는 규칙이고, 자동 메모리는 Claude가 내 부탁을 보고 스스로 적어 두는 메모예요.
공식 문서는 "기억해 줘"라고 부탁하면 자동 메모리에 저장되고, CLAUDE.md에 넣고 싶다면 "CLAUDE.md에 추가해 줘"라고 말하라고 안내합니다.

제 시험에서는 조금 다르게 보였어요.
"앞으로 pnpm을 써 줘. 기억해 둬."라고 했더니 자동 메모리가 아니라 프로젝트의 CLAUDE.md에 한 줄이 적혔습니다.

대화 없이 한 번에 실행하는 방식이었고, 문서에도 일부 실행 환경에서는 자동 메모리가 꺼진다는 설명이 있어요.
정확한 원인은 확인하지 못했으니, 평소 쓰는 화면에서 `/memory`를 열어 직접 확인해 보시길 권합니다.

**Q. 인터넷 글에서 `#`을 입력해 메모를 추가한다던데요?**
예전 자료에 나오는 방법이고 지금 공식 문서에는 없습니다.
현재는 Claude에게 "이걸 CLAUDE.md에 추가해 줘"라고 말하거나 `/memory`로 직접 고치는 방법을 안내해요.
