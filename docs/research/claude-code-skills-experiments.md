# 실험 기록: 클로드 코드 스킬 사용법 글의 '직접 해 본 결과'

- 실행일: 2026-10-28
- 도구: Claude Code 2.1.312, `claude -p "<요청>" --output-format stream-json --verbose` (대화 없이 한 번 실행하고, 도구 호출 기록까지 받는 방식)
- 판정 방법: Claude가 스스로 스킬을 고르면 기록에 `Skill` 도구 호출(스킬 이름 포함)이 남는다. 이것으로 "자동으로 불렸는지"를 판정했다. `/이름`으로 직접 부른 경우는 도구 호출 없이 스킬 내용이 바로 들어가므로, 스킬 본문에 넣은 표시 문구(`[○○ 스킬 사용]`)가 답 첫 줄에 나오는지로 판정했다.
- 환경: 클라우드 컨테이너. 개인 스킬(`~/.claude/skills/`)이 섞이지 않도록 빈 홈 폴더(`HOME=<빈 폴더>`)로 실행했다. 스킬은 모두 프로젝트 스킬(`.claude/skills/`)로 두었다.
- 연습 프로젝트: 앞 글들과 같은 할 일 목록 예제(`index.html`, `style.css`, `app.js`, `old/legacy.js`)를 git으로 만들고 커밋 1개를 둔 상태. 실험마다 새로 복사했다.
- 한계: 자동 호출은 Claude의 판단이라 매번 같지 않을 수 있다. 각 2~3회 실행 결과이고 통계적 결론이 아니다.

## 실험 1. 첫 스킬: 공식 예제를 한국어로 (글 3절)
- 스킬: `.claude/skills/summarize-changes/SKILL.md` (공식 첫 예제 `summarize-changes`를 한국어로 옮긴 것. 본문에 `` !`git diff HEAD` ``로 변경 내용을 넣음)
- 준비: `app.js`에 두 군데 변경(빈 입력이면 추가하지 않는 한 줄, 쓰이지 않는 상수 `MAX_ITEMS = 20` 한 줄). `git diff --stat`: 1 file changed, 3 insertions.
- 자동: "뭐 바꿨는지 알려 줘" → `Skill` 도구로 `summarize-changes` 호출. 답은 '바뀐 내용' 2개 + '눈에 띄는 위험'(공백만 입력하면 그대로 추가됨, `MAX_ITEMS`가 쓰이지 않음, 사용자 알림 없음, 테스트) 형식.
- 직접: `/summarize-changes` → 같은 형식('변경 요약' + '눈에 띄는 위험')의 답. 두 경우 모두 스킬 지시(두세 개 글머리표 요약 → 위험 나열)를 따름.
- `` !`git diff HEAD` ``는 별도 허용 설정 없이 실행되어 변경 내용이 답에 반영됨.

## 실험 2. 설명(description)이 자동 호출을 좌우하는가 (글 4절)
- 같은 요청 3회씩: "이 문장 맞춤법 좀 봐 줘: 오늘 날씨가 너무 좋와서 산책을 갔는데 금새 비가 왔다."
- 스킬 본문은 모두 같음(첫 줄에 `[이름 스킬 사용]` 표시, 고친 문장과 "고치기 전 | 고친 뒤 | 이유" 표).

| 경우 | name | description | 자동 호출 |
| :-- | :-- | :-- | :-- |
| A | `proofread-ko` | 구체적: "한국어 문장의 맞춤법과 띄어쓰기를 고치고, 바뀐 곳을 표로 보여 준다. 사용자가 맞춤법 검사, 띄어쓰기 확인, 오타 교정, 문장 다듬기를 부탁할 때 사용한다." | 3/3 |
| B | `proofread-ko` | 모호: "문장 관련 작업을 한다." | 3/3 |
| C | `helper` | 모호: "도움을 준다." | 0/3 (Claude가 스킬 없이 직접 교정) |
| D | `helper` | A와 같은 구체적 설명 | 3/3 |

- 해석: B는 설명이 모호해도 이름(`proofread-ko`)이 단서가 되어 불렸다(스킬이 하나뿐인 환경). 이름까지 모호한 C는 한 번도 불리지 않았고, 이름이 모호해도 설명이 구체적인 D는 매번 불렸다. 이름과 설명 모두 판단 재료이고, 특히 설명이 구체적이면 이름과 상관없이 불렸다.

## 실험 3. 내가 부를 때만 + 인자 (글 4절)
- 스킬: `.claude/skills/blog-titles/SKILL.md`, `disable-model-invocation: true`, `argument-hint: [주제]`, 본문 첫 줄 지시 `` `[blog-titles 스킬 사용] 주제: $ARGUMENTS` ``
- 자동 시도 2회: "클로드 코드 스킬 주제로 블로그 제목 5개 지어 줘" → 2회 모두 `Skill` 호출 없음, 표시 문구 없음(Claude가 스킬 없이 직접 제목을 지음).
- 직접: `/blog-titles 클로드 코드 스킬` → 첫 줄 `[blog-titles 스킬 사용] 주제: 클로드 코드 스킬`(`$ARGUMENTS`가 입력한 말로 바뀜), 이어서 번호 목록 제목 5개.

## 실험 4. 필드 이름 철자가 틀리면 (글 5절)
- 실험 3과 같고 `disable-model-invocation`을 `disable-model-invokation`(c→k)으로만 바꿈.
- 같은 자동 요청 2회 → 2회 모두 `Skill` 도구로 `blog-titles` 호출. 오류나 경고 없이 틀린 필드가 무시되어 자동 호출이 그대로 일어남(공식 문서의 "모르는 필드는 무시" 설명과 일치).

## 재현
1. 할 일 목록 예제를 만들고 `git init` 후 커밋한다.
2. 위 내용으로 `.claude/skills/<이름>/SKILL.md`를 만들고 같은 요청을 `claude -p`로 보낸다. 자동 호출 여부는 `--output-format stream-json --verbose` 출력에서 `"name":"Skill"` 도구 호출을 찾는다.
