# 실험 기록: 클로드 코드 서브에이전트 사용법 글의 '직접 해 본 결과'

- 실행일: 2026-10-28
- 도구: Claude Code 2.1.312, `claude -p "<요청>" --output-format stream-json --verbose` (대화 없이 한 번 실행하고, 도구 호출 기록까지 받는 방식)
- 판정 방법: 기록에서 메인 대화의 도구 호출과 서브에이전트 안의 도구 호출을 나눠 셌다(서브에이전트 쪽 기록에는 `parent_tool_use_id`가 붙는다). 서브에이전트에 맡겼는지는 메인 대화의 `Agent` 도구 호출과 그 `subagent_type`으로 판정했다. "메인 대화로 돌아온 분량"은 메인 대화가 받은 도구 결과의 글자 수 합계다.
- 환경: 클라우드 컨테이너. 개인 설정(`~/.claude/agents/` 등)이 섞이지 않도록 빈 홈 폴더(`HOME=<빈 폴더>`)로 실행했다. 직접 만든 서브에이전트는 모두 프로젝트의 `.claude/agents/`에 두었다.
- 연습 프로젝트: 이 저장소의 식단 기록 앱 백엔드(`backend/app`, 파이썬 파일 30개, 약 172KB)를 복사해 git으로 만든 폴더. 앞 글들의 할 일 목록 예제(파일 4개)는 조사 실험에 너무 작아서 바꿨다. 실험마다 새로 복사했다.
- 한계: 맡길지 말지는 Claude의 판단이라 매번 같지 않을 수 있다. 각 1~3회 실행 결과이고 통계적 결론이 아니다.

## 실험 1. 직접 조사 vs Explore 서브에이전트에 맡기기 (글 1절)
- 질문(공통): "이 프로젝트에서 로그인 토큰을 어떻게 만들고, 어디에 저장하고, 요청마다 어떻게 검사하는지 다섯 줄 이내로 정리해 줘."
- 직접: 앞에 "서브에이전트는 쓰지 말고 직접 파일을 읽어서 조사해 줘."를 붙임
- 맡김: 앞에 "Explore 서브에이전트에게 맡겨서 조사해 줘."를 붙임

| 회차 | 방식 | 메인 대화의 도구 호출 | 서브에이전트 안의 도구 호출 | 메인 대화로 돌아온 분량(글자) | 최종 답(글자) |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 직접 | 5회 (Read 3, Bash 2) | 없음 | 21,452 | 895 |
| 1 | Explore에 맡김 | 1회 (Agent 1) | 4회 | 6,299 | 843 |
| 2 | 직접 | 2회 (Bash 2) | 없음 | 28,172 | 933 |
| 2 | Explore에 맡김 | 1회 (Agent 1) | 4회 | 4,235 | 995 |

- 두 방식 모두 답의 핵심은 같았다: JWT가 아닌 무작위 토큰을 `secrets.token_urlsafe(32)`로 만들고, 서버 DB(`sessions`)에 기록해 요청마다 대조한다.
- 메인 대화로 돌아온 분량은 맡겼을 때가 직접 했을 때의 약 1/6~1/3(4,235~6,299자 vs 21,452~28,172자).

## 실험 2. 읽기 전용 서브에이전트에게 파일 수정을 맡기면 (글 3·4절)
- 에이전트: `.claude/agents/reviewer.md`

```markdown
---
name: reviewer
description: 코드를 읽고 버그·보안 문제를 찾아 근거와 함께 보고하는 읽기 전용 리뷰어. 사용자가 코드 리뷰, 검토, 점검, 버그 찾기를 요청하면 사용한다.
tools: Read, Grep, Glob
---

당신은 코드 리뷰어다. 코드를 읽고 버그, 보안 문제, 읽기 어려운 부분을 찾아 근거(파일:줄)와 함께 보고한다.
보고 첫 줄에 반드시 `[reviewer 에이전트 보고]`라고 쓴다.
파일을 고치지 않는다. 고칠 방법은 제안으로만 적는다.
```

- 요청: "reviewer 서브에이전트에게 맡겨서 app/config.py 맨 위에 '# 검토 완료' 주석 한 줄을 추가하게 해 줘. 너는 직접 파일을 고치지 말고, 서브에이전트가 한 결과만 그대로 전해 줘."
- 2-A (위 파일 그대로, 기본 권한 모드): `reviewer`가 불렸고 파일은 그대로. 답: "reviewer가 쓸 수 있는 도구는 Read, Grep, Glob뿐이라 파일을 고칠 수 없습니다" + 역할 지침도 이유로 듦.
- 이유를 가르기 위한 추가 실험(둘 다 본문의 "파일을 고치지 않는다…"를 "요청받으면 파일도 직접 고친다."로 바꾸고, 파일 수정 자동 승인 `--permission-mode acceptEdits`로 실행):

| 경우 | `tools` 줄 | 결과 |
| :-- | :-- | :-- |
| 2-B | `tools: Read, Grep, Glob` | 수정 못 함. 파일 그대로. "쓸 수 있는 도구는 Read, Grep, Glob뿐" |
| 2-C | 없음(생략) | 첫 줄에 `# 검토 완료` 추가됨 |

- 해석: 지침이 "고쳐라"여도 `tools`에 수정 도구가 없으면 고치지 못했다. `tools`를 생략한 에이전트는 수정 도구를 물려받아 실제로 고쳤다.

## 실험 3. 설명(description)에 따라 알아서 맡기는가 (글 4절)
- 같은 요청 3회씩: "app/api/ratelimit.py 코드 리뷰해 줘. 버그가 있으면 알려 줘." (기본 권한 모드)
- 에이전트 본문과 `tools: Read, Grep, Glob`은 같고 `description`만 다름.

| 경우 | description | reviewer에 맡긴 횟수 |
| :-- | :-- | :-- |
| 모호 | "도움을 준다." | 0/3 (세 번 모두 Claude가 직접 리뷰) |
| 구체적 | "코드를 읽고 버그·보안 문제를 찾아 근거와 함께 보고하는 읽기 전용 리뷰어. 사용자가 코드 리뷰, 검토, 점검, 버그 찾기를 요청하면 사용한다." | 1/3 |
| 구체적 + 적극 사용 문구 | "코드를 읽고 버그·보안 문제를 찾아 근거와 함께 보고하는 읽기 전용 리뷰어. Use proactively: 사용자가 코드 리뷰, 검토, 점검, 버그 찾기를 요청하면 직접 하지 말고 반드시 먼저 이 에이전트에게 맡긴다." | 3/3 |

- 셋째 설명은 콜론+공백(`Use proactively: `)이 들어가 YAML이 깨지지 않도록 큰따옴표로 감쌌다(파싱 확인함).
- 해석: 파일 하나짜리 작은 리뷰는 Claude가 직접 하는 경우가 많았다. 설명이 구체적인 것만으로는 1/3이었고, "적극적으로 쓰라"는 문구를 넣자 3/3 맡겼다. 다만 요청이 작고 회수가 적어 일반화하기는 어렵다.

## 재현
1. 아무 프로젝트를 git으로 만든 뒤 `.claude/agents/<이름>.md`에 위 파일을 둔다.
2. 같은 요청을 `claude -p "<요청>" --output-format stream-json --verbose`로 보내고, 출력에서 `"name":"Agent"` 도구 호출과 그 `subagent_type`을 찾는다.
