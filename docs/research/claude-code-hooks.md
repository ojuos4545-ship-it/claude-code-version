# 리서치 노트: 클로드 코드 훅 사용법

- 조사일: 2026-10-27
- 기준 시점: 2026-10-27에 연 Claude Code 공식 문서, 실험은 Claude Code 2.1.312
- 목적/독자: 블로그 글(정보 취득용). 독자는 클로드 코드 입문자. 앞선 글 'CLAUDE.md 작성법'의 다음 편으로, 앞 글 끝에서 예고한 '훅'을 다룬다.

## 1. 결론 요약

- 훅은 클로드 코드가 정해진 시점(도구 실행 전·후, 응답 종료, 알림 등)에 **내가 정한 셸 명령을 자동으로 실행**하게 하는 설정이다. 모델이 고르는 게 아니라 하네스가 매번 실행한다는 점이 CLAUDE.md와 다르다 [1][3].
- 설정은 `settings.json`의 `hooks` 블록에 `이벤트 → matcher → 실행할 명령` 구조로 적는다. 위치는 내 모든 프로젝트용(`~/.claude/settings.json`), 프로젝트 공유용(`.claude/settings.json`), 나만 쓰는 프로젝트용(`.claude/settings.local.json`)이 기본이다 [1][2].
- 입문자가 먼저 써 볼 만한 공식 예제는 알림(`Notification`), 수정 후 자동 정리(`PostToolUse` + Prettier), 보호 파일 차단(`PreToolUse` + `exit 2`) 세 가지다 [1].
- 막는 훅은 반드시 `exit 2`로 끝나야 한다. `exit 1`은 오류로만 기록되고 작업은 그대로 진행된다 [1][2]. 실험에서도 같은 결과를 확인했다(실험 기록 4).
- 명령 훅은 내 사용자 권한 그대로 실행되므로, 추가 전에 내용을 직접 읽고 시험해야 한다 [2].

## 2. 질문별 조사 결과

### Q1. 훅은 무엇이고 CLAUDE.md와 무엇이 다른가?
- [사실] 훅은 사용자가 정의한 셸 명령으로, 클로드 코드 라이프사이클의 특정 시점에 실행되며 "결정론적 통제"를 준다. 모델이 실행 여부를 고르지 않는다 (출처 [1])
- [사실] 모범 사례 문서는 지시를 둘로 나눈다. 프롬프트·CLAUDE.md·스킬은 모델이 읽고 판단하는 비결정적 지시로 따를 것이 보장되지 않고, 훅·deny 규칙·관리 설정은 하네스가 매번 적용하는 결정적 지시다 (출처 [3])
- [사실] "꼭 매번 일어나야 하는 일은 훅이나 deny 규칙으로, CLAUDE.md는 지침용"이라고 안내한다. 반대로 단순 선호를 훅으로 만들었다면 지우라고 권한다 (출처 [3])
- [사실] 판단이 필요한 경우를 위한 `prompt`·`agent` 훅도 있지만 다른 모델이 판단하므로 결정적이지 않다. `agent` 훅은 실험 기능이다 (출처 [1][3])
- 신뢰도: 높음

### Q2. 어디에, 어떤 구조로 설정하는가?
- [사실] 설정 위치와 범위 (출처 [1][2])

  | 위치 | 범위 | 공유 |
  | :-- | :-- | :-- |
  | `~/.claude/settings.json` | 내 모든 프로젝트 | 아니오(내 컴퓨터만) |
  | `.claude/settings.json` | 한 프로젝트 | 예(저장소에 커밋 가능) |
  | `.claude/settings.local.json` | 한 프로젝트 | 아니오(클로드 코드가 저장할 때 gitignore 처리) |
  | 관리 정책 설정 | 조직 전체 | 관리자 |
  | 플러그인 `hooks/hooks.json` | 플러그인 사용 중 | 예 |
  | 스킬·서브에이전트 프론트매터 | 해당 스킬·서브에이전트 동작 중 | 예 |

- [사실] 여러 위치의 훅은 서로 덮어쓰지 않고 합쳐진다 (출처 [2])
- [사실] 구조는 `"hooks"` 객체 안에 이벤트 이름을 키로 두고, 그 안에 `matcher`와 `hooks` 배열(`type`, `command`)을 둔다. 이미 `hooks` 키가 있으면 통째로 바꾸지 말고 이벤트 키를 형제로 추가한다 (출처 [1])
- [사실] matcher는 `"*"`·빈 값·생략이면 전부, 글자·숫자·`_`·`-`·공백·`,`·`|`만 쓰면 정확한 이름 목록, 그 밖의 문자가 있으면 정규식으로 해석한다. 대소문자를 구분한다 (출처 [1][2])
- [사실] 클로드 코드 실행 중에 설정 파일을 직접 고치면 파일 감시로 보통 자동 반영된다. 몇 초 뒤에도 안 보이면 세션을 다시 시작한다 (출처 [1])
- [사실] `/hooks`는 설정된 훅을 이벤트별로 보여 주는 읽기 전용 화면이다. 추가·수정은 설정 파일을 직접 고치거나 Claude에게 부탁한다 (출처 [1][2])
- 신뢰도: 높음

### Q3. 어떤 이벤트가 있고, 입문자는 무엇부터 쓰면 좋은가?
- [사실] 조사일 기준 훅 이벤트는 33개다 (출처 [2]). 입문자에게 필요한 것만 추리면 아래와 같다 (출처 [1])

  | 이벤트 | 시점 |
  | :-- | :-- |
  | `SessionStart` | 세션 시작·재개 |
  | `UserPromptSubmit` | 프롬프트를 보낸 직후, Claude가 처리하기 전 |
  | `PreToolUse` | 도구 실행 전. 막을 수 있음 |
  | `PostToolUse` | 도구 실행이 성공한 뒤. 이미 실행돼 되돌릴 수 없음 |
  | `Notification` | 클로드 코드가 알림을 보낼 때(입력·권한 대기 등) |
  | `Stop` | Claude가 응답을 마쳤을 때. 사용자가 중단하면 울리지 않음 |
  | `SessionEnd` | 세션 종료 |

- [해석] 입문자는 "알림 → 자동 정리 → 막기" 순으로 써 보는 것이 공식 가이드의 예제 순서와 맞고, 위험도도 낮은 것부터 올라간다.
- 신뢰도: 높음

### Q4. 훅은 어떻게 입력을 받고 결과를 돌려주는가?
- [사실] 이벤트가 일어나면 JSON이 표준 입력(stdin)으로 들어온다. 공통 필드(`session_id`, `cwd`, `hook_event_name` 등)에 도구 이벤트는 `tool_name`, `tool_input`이 더해진다 (출처 [1][2])
- [사실] 종료 코드 (출처 [1][2])
  - `0`: 이의 없음. `PreToolUse`에서 0은 승인이 아니며 평소 권한 절차를 그대로 탄다
  - `2`: 차단. stderr에 쓴 이유가 (이벤트에 따라) Claude에게 피드백으로 전달된다. 막을 수 없는 이벤트(`PostToolUse`, `Notification`, `SessionStart` 등)에서는 막지 못한다
  - 그 밖(예: `1`): 막지 않는 오류. 작업은 진행된다. 정책을 강제하려면 `exit 2`를 쓰라고 문서가 직접 경고한다
- [사실] 여러 훅이 같은 이벤트에 걸리면 병렬로 실행되고, 하나라도 거부하면 거부가 우선한다 (출처 [1])
- [사실] 훅이 `"deny"`로 막은 도구는 `bypassPermissions` 모드에서도 막힌다 (출처 [1])
- 신뢰도: 높음

### Q5. 입문자용 공식 예제는 무엇인가?
- [사실] 알림: `~/.claude/settings.json`에 `Notification` 훅. macOS `osascript`, Linux `notify-send`, Windows PowerShell 명령을 각각 제시 (출처 [1])
- [사실] 자동 정리: `.claude/settings.json`에 `PostToolUse`, matcher `Edit|Write`, 명령 `jq -r '.tool_input.file_path' | xargs npx prettier --write`. `jq` 설치 필요 (출처 [1])
- [사실] 보호 파일 차단: `.claude/hooks/protect-files.sh`가 경로에 `.env`, `package-lock.json`, `.git/`가 들어 있으면 stderr에 이유를 쓰고 `exit 2`. `chmod +x` 후 `PreToolUse`, matcher `Edit|Write`로 등록 (출처 [1])
- [사실] Claude는 셸 명령으로도 파일을 만들거나 바꿀 수 있으므로, 모든 파일 변경을 잡아야 한다면 `Stop` 훅 등 다른 방법을 함께 쓰라고 안내한다 (출처 [1])
- 신뢰도: 높음

### Q6. 안 될 때는 어떻게 확인하는가?
- [사실] `/hooks`에서 해당 이벤트 아래에 보이는지 확인, matcher 대소문자 확인 (출처 [1])
- [사실] 스크립트에 예시 JSON을 넣어 직접 돌려 보고 `echo $?`로 종료 코드 확인 (출처 [1])
- [사실] "command not found"면 절대 경로나 `$CLAUDE_PROJECT_DIR` 사용, 스크립트가 아예 안 돌면 `chmod +x` (출처 [1])
- [사실] JSON에는 끝 쉼표·주석을 쓸 수 없다 (출처 [1])
- [사실] `Ctrl+O`로 트랜스크립트 보기, `claude --debug-file /tmp/claude.log`로 디버그 로그 (출처 [1])
- 신뢰도: 높음

### Q7. 보안상 주의할 점은?
- [사실] 명령 훅은 내 사용자 권한 전체로 셸 명령을 실행하므로 추가 전에 검토·시험하라는 경고 (출처 [2])
- [사실] 대화형 세션은 폴더 신뢰 확인 창을 수락하기 전까지 설정 파일의 훅을 실행하지 않는다. `-p`(비대화형)·SDK 세션은 확인 창 없이 신뢰로 간주하므로, 남이 만든 저장소에서는 `.claude/` 설정을 먼저 읽거나 `--settings '{"disableAllHooks": true}'`로 끈다 (출처 [2])
- [사실] 권장 습관: 입력 검증, 셸 변수는 `"$VAR"`로 감싸기, `..` 경로 차단, 절대 경로, `.env`·`.git/`·키 파일 피하기 (출처 [2])
- [사실] 모든 훅을 잠시 끄려면 `"disableAllHooks": true`. 훅 하나만 끄는 스위치는 없고 지워야 한다 (출처 [2])
- 신뢰도: 높음

## 4. 상충하거나 불확실한 내용

- `/hooks`에서 훅을 바로 추가할 수 있다는 예전 블로그 글이 검색된다. 조사일 기준 공식 문서는 `/hooks`를 읽기 전용 화면으로 설명한다. 글에서는 "설정 파일을 고치거나 Claude에게 부탁한다"로 쓴다.
- `Notification` 훅은 비대화형(`claude -p`) 실행에서는 울리지 않았다(실험 기록 1). 문서상 입력·권한을 기다릴 때 울리는 이벤트이므로 예상과 맞지만, 대화형 환경에서의 데스크톱 알림은 이 컨테이너에 화면이 없어 직접 확인하지 못했다.

## 5. 글쓰기 에이전트에게 (활용 가이드)

- 핵심 메시지: "CLAUDE.md는 부탁, 훅은 규칙." 꼭 지켜야 하는 일만 훅으로, 나머지는 CLAUDE.md로.
- 앞 글과의 연결: 앞 글 4절 끝에서 "꼭 막을 일은 '훅'이라는 자동 실행 기능을 쓰라는 것이 공식 안내"라고 예고했다. 이번 글이 그 실습편이다.
- FAQ 후보: 훅을 Claude에게 만들어 달라고 해도 되나요?(예, 공식 문서가 안내) / 훅을 잠시 끄려면?(`disableAllHooks`) / 막는 훅인데 안 막혀요(`exit 1` 여부, matcher 대소문자)
- 장단점: 장점(매번 실행, 잊어버릴 일 없음, 팀 공유 가능) / 주의(내 권한으로 실행, 너무 많으면 관리 부담, `Edit|Write`만 보면 셸 명령 변경은 못 잡음)
- 연관 키워드: 클로드 코드 hooks, 클로드 코드 자동화, settings.json, PreToolUse, PostToolUse, 클로드 코드 알림
- 주의: 이벤트 수(33개)·버전은 업데이트로 바뀐다. "조사일 기준"을 붙인다. Linux·Windows 알림 명령은 직접 확인하지 못했으니 "공식 문서 예시"로만 소개한다.
- 직접 경험: 실험 기록(`docs/research/claude-code-hooks-experiments.md`)에 있는 결과만 체험으로 쓴다.

## 용어 설명

- 하네스: Claude(모델)를 감싸고 도구 실행·권한·설정을 관리하는 클로드 코드 프로그램 자체.
- matcher: 훅이 어떤 도구(또는 상황)에서만 실행될지 거르는 조건.
- stdin / stderr: 프로그램이 입력을 받는 통로 / 오류 메시지를 내보내는 통로.
- 종료 코드(exit code): 명령이 끝나며 남기는 숫자. 0은 정상, 그 밖은 문제가 있었다는 뜻.
- `jq`: JSON에서 원하는 값만 뽑아 주는 명령줄 도구.
- Prettier: 코드 모양(따옴표, 들여쓰기 등)을 정해진 규칙대로 정리해 주는 도구.
