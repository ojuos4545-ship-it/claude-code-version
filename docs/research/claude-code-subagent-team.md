# 리서치 노트: 클로드 코드 서브에이전트로 역할별 팀 꾸리기

- 조사일: 2026-10-27
- 기준 시점: 2026-10-27에 연 공식 문서 https://code.claude.com/docs/en/sub-agents (원문 116,349자 중 앞 100,000자까지 확인, 뒷부분 16,349자는 읽지 못함)
- 목적/독자: 네이버 블로그 가이드형 글. 서브에이전트를 처음 직접 만들어 보려는 사용자.
- 직접 경험의 근거: 이 저장소의 git 기록과 `.claude/agents/` 파일. 기록에 없는 시간·횟수·감상은 쓰지 않는다.

## 1. 결론 요약
- [사실] 서브에이전트는 `.claude/agents/<이름>.md` 파일 한 장(YAML 프론트매터 + 본문 프롬프트)으로 만든다. 필수 필드는 `name`, `description`뿐이다 [1].
- [사실] 본문은 서브에이전트의 시스템 프롬프트가 되고, `description`은 Claude가 언제 위임할지 판단하는 기준이다 [1].
- [해석] 역할별로 파일을 나누고 도구 권한을 다르게 주면 "기획 → 구현 → 검증"을 한 대화에서 순서대로 맡길 수 있다.

## 2. 사실 목록 (출처 [1])
- 프론트매터 필드: name, description(필수) / tools, disallowedTools, model, permissionMode, maxTurns, skills, mcpServers, hooks, memory, background, effort, isolation, color 등(선택). 다단어 필드는 camelCase. 인식되지 않는 필드는 오류 없이 무시된다.
- `tools`를 생략하면 쓸 수 있는 모든 도구를 상속한다. `disallowedTools`는 먼저 적용된다.
- `model`: sonnet, opus, haiku, fable, 전체 모델 ID, `inherit`(메인 대화 모델).
- `color`: red, blue, green, yellow, purple, orange, pink, cyan.
- 저장 위치와 우선순위(높음→낮음): 관리형 설정 > `--agents` 플래그 > `.claude/agents/`(프로젝트) > `~/.claude/agents/`(모든 프로젝트) > 플러그인. 같은 `name`이면 우선순위가 높은 쪽이 쓰인다. 하위 폴더도 재귀 스캔하며 식별은 `name`으로만 한다.
- 위임: 요청, description, 현재 맥락을 보고 Claude가 판단한다. "use proactively" 같은 문구를 넣으면 자동 위임이 늘어난다. 직접 지목(`@"code-reviewer (agent)"` 또는 자연어)도 된다. description 합계가 15,000 토큰을 넘으면 시작 시 경고가 뜨니 짧게 쓰고 자세한 건 본문에 둔다.
- 연결(체이닝): 한 프롬프트에서 "A로 찾고, 그다음 B로 고쳐" 식으로 순서를 말한다. 각 결과는 메인 Claude에게 돌아오고 Claude가 다음 서브에이전트에 필요한 맥락을 넘긴다.
- 중첩: 서브에이전트가 또 다른 서브에이전트를 부르려면 `tools`에 `Agent`가 있어야 하고, 기본 최대 3계층이다(v2.1.219부터). 동시 실행 기본 20개.
- 주의: 일반 서브에이전트는 대화 기록, 읽은 파일, 호출한 스킬을 모른다. 위임 메시지에 작업을 요약해 줘야 한다. 대부분의 서브에이전트는 CLAUDE.md를 로드한다(Explore·Plan 제외). 토큰은 서브에이전트마다 따로 쓰이고 결과 크기만큼 메인 컨텍스트를 차지한다.
- 프론트매터가 잘못되면 오류 없이 건너뛴다: `name` 없음, 여는 `---`가 첫 줄이 아님은 조용히 건너뜀. name 형식 오류, description 없음, YAML 파싱 실패는 `--debug` 로그에만 남는다. `name`에 콜론은 쓸 수 없다. `/doctor`가 같은 이름 중복을 알려 준다.
- 인식 시점: 대부분 재시작 없이 몇 초 안에 감지되어 다음 위임부터 반영된다. 해당 범위에 `agents` 디렉터리를 처음 만든 경우와 `--add-dir`로 추가한 디렉터리는 재시작이 필요하다.

## 3. 저장소에서 확인한 사실 (직접 경험 재료)
- [저장소] 2026-10-26 하루 동안 코드 리뷰어, 프로덕트 매니저, 백엔드 개발자, QA 엔지니어 에이전트 4종을 `.claude/agents/`에 추가했다(커밋 7234be2, 8cd1e0b, 8e8da26).
- [저장소] 같은 날 PRD 초안(467d3e0) → 미결 사항 반영(69fe5c4) → MVP 백엔드(d5f6051) → 리뷰 반영(8b49ed3) → 웹 클라이언트(3954361) → 보안 항목(06357a8) → QA 버그 재현 테스트 "수정 전, 일부 실패"(11c6c4f) → 리뷰·QA 지적 6건 수정(4134507) 순서로 진행했다.
- [저장소] 프로덕트 매니저는 `tools: Read, Glob, Grep, WebFetch, WebSearch, Write, Edit`(Bash 없음)로 제한했고, 백엔드 개발자·QA·코드 리뷰어는 `tools`를 생략해 모든 도구를 상속한다. 코드 리뷰어의 "읽기 전용"은 도구 제한이 아니라 프롬프트 지침이다.
- [저장소] QA 엔지니어는 테스트 코드만 쓰고 제품 코드는 지시 없이 고치지 않는다는 규칙, 코드 리뷰어와는 "읽기만 하는 리뷰 vs 직접 실행하는 검증"으로 역할을 나눴다.
- [저장소] 프로젝트 `CLAUDE.md`에는 "description 값에 `: `(콜론+공백)이 들어가면 YAML 파싱이 깨진다", "파일 이름과 `name`을 같게 맞춘다", "프롬프트는 한국어, 보고서는 결론 먼저"라는 규칙을 적어 두었다. 또 "새로 추가한 에이전트는 새 세션부터 인식된다"고 적었는데, 공식 문서는 대부분 몇 초 안에 감지된다고 한다. 환경에 따라 다를 수 있다고만 쓴다.
- [저장소] 에이전트들은 PRD(`docs/prd/`)를 공통 기준으로 삼는다: PM이 쓰고, 백엔드가 구현하고, QA가 수용 기준으로 검증한다.
