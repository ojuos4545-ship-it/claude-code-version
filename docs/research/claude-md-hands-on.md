- 조사일: 2026-10-27
- 기준 시점: 2026-10-27에 연 공식 문서. 문서에 발행일 표기는 없다. 공식 changelog에서 확인한 가장 높은 버전은 2.1.311이다 [7].
- 목적/독자: 네이버 블로그 가이드형(How-to), 목적은 정보 취득. 독자는 Claude Code 입문자(코딩 경험 적음, CLAUDE.md가 왜 필요한지 모름).
- 시리즈 후속편: 앞선 노트 `claude-code-core-features.md`(CLAUDE.md 개요, `/init`, 200줄 권장, AGENTS.md 등 기본 사실)와 `claude-code-subagent-team.md`(서브에이전트가 CLAUDE.md를 읽는다는 사실)는 반복 조사하지 않고, 이번에 원문으로 재확인하면서 새 내용을 더했다.

## 1. 결론 요약

- [사실] CLAUDE.md는 내가 평문(마크다운)으로 쓰는 지침 파일이고, Claude는 세션을 시작할 때마다 읽는다. 세션은 매번 빈 컨텍스트로 시작하므로 이 파일이 "매번 다시 설명해야 할 것"을 대신 기억한다 [1].
- [사실] 프로젝트 루트의 `./CLAUDE.md`(또는 `./.claude/CLAUDE.md`)가 기본 자리다. 시작은 `/init`으로 초안을 만들고, 줄이는 쪽으로 다듬는다. 파일당 200줄 이하가 권장이다 [1][2].
- [사실] 적을 것은 "코드를 읽어도 알 수 없는 것"(테스트 명령, 함정, 팀 결정, 두 번 고쳐 준 것)이다. 파일 구조·아키텍처 설명은 Claude가 직접 읽으니 적지 않는 편이 낫다 [2].
- [사실] CLAUDE.md는 강제 규칙이 아니라 "맥락"이다. 반드시 지켜야 하는 것은 훅·deny 규칙으로 옮긴다 [1][2].
- [사실, 최신 변경] 예전 자료에 나오던 `#`로 시작해 메모리를 추가하는 방법은 현재 공식 문서에 없다. 지금 공식 안내는 "Claude에게 'CLAUDE.md에 추가해'라고 말하거나 `/memory`로 직접 편집"이다 [1][5][6].

## 2. 질문별 조사 결과

### Q1. CLAUDE.md는 무엇이고 왜 필요한가? 쓰기 전/후

- [사실] 매 세션은 새 컨텍스트 창으로 시작한다. 이를 이어 주는 장치가 두 가지다: 내가 쓰는 CLAUDE.md, Claude가 스스로 쓰는 자동 메모리 [1].
- [사실] CLAUDE.md는 "다시 설명하게 될 것을 적어 두는 곳"이다. 추가할 때의 공식 기준 4가지: (1) Claude가 같은 실수를 두 번째 할 때 (2) 코드 리뷰에서 "이 코드베이스에선 알았어야 할 것"이 지적될 때 (3) 지난 세션과 같은 교정을 또 입력할 때 (4) 새 팀원도 같은 맥락이 필요할 때 [1].
- [사실] 공식 모범 사례는 세션이 기대와 다르게 흘러가는 흔한 원인 하나를 "Claude가 repo를 읽어서는 알 수 없는 정보가 빠져 있거나, 매 세션 같은 사실을 다시 찾아야 하는 것"으로 든다. 배포 절차가 사람 머릿속에만 있는 경우, 통합 테스트에 필요한 환경 변수 같은 것이 예다 [2].
- [사실] CLAUDE.md 내용은 시스템 프롬프트가 아니라 시스템 프롬프트 뒤의 사용자 메시지로 전달된다. 따라서 엄격한 준수가 보장되지 않는다 [1].
- [해석] 쉬운 비유 후보 (공식 문서의 비유가 아니라 내 제안):
  - "매번 첫 출근하는 신입에게 주는 인수인계 메모": 이 신입은 어제 일을 기억하지 못하니, 책상에 메모를 붙여 둔다.
  - "단골 식당에 맡겨 둔 내 취향 카드": 매번 말하지 않아도 '덜 맵게, 땅콩 알레르기'를 안다.
  - 단, 메모는 '지시서'가 아니라 '참고 자료'라서 100% 지켜진다고 약속하지 않는다는 점도 함께 쓰는 편이 정확하다 [1].
- [해석] 쓰기 전/후 대비 (일반화된 시나리오이며 경험담이 아님): 전에는 "테스트는 이렇게 돌려"를 대화마다 반복 입력, 후에는 파일에 한 줄 적어 두면 새 세션부터 Claude가 그 명령을 안다. 실제 체감은 필자 경험으로 채워야 한다.
- 신뢰도: 높음 (공식 문서 2곳 일치 [1][2])

### Q2. 어디에 둘 수 있고, 어떻게 로드되나

- [사실] 위치별 범위(공식 표, 넓은 범위부터 구체적인 순서로 로드, 구체적인 지침이 컨텍스트에서 나중에 나온다) [1]:

| 범위 | 위치 | 용도 | 공유 대상 |
| :-- | :-- | :-- | :-- |
| 조직 관리형 | macOS `/Library/Application Support/ClaudeCode/CLAUDE.md`, Linux·WSL `/etc/claude-code/CLAUDE.md`, Windows `C:\Program Files\ClaudeCode\CLAUDE.md` | IT·DevOps가 배포하는 조직 공통 지침 | 조직 전원 |
| 사용자 전체 | `~/.claude/CLAUDE.md` | 모든 프로젝트에 적용되는 개인 선호 | 나만 |
| 프로젝트 | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 팀 공유 프로젝트 지침 | 버전 관리로 팀원 |
| 로컬(개인·프로젝트별) | `./CLAUDE.local.md` (.gitignore에 추가) | 이 프로젝트에서만 쓰는 개인 설정 | 나만 |

- [사실] 로드 방식: 현재 작업 폴더와 그 위쪽 모든 폴더의 `CLAUDE.md`·`CLAUDE.local.md`를 시작할 때 읽는다. 파일들은 덮어쓰지 않고 이어 붙여지며, 루트에서 작업 폴더 쪽으로 내려오는 순서라 작업 폴더에 가까운 지침이 나중에 읽힌다. 같은 폴더에서는 `CLAUDE.local.md`가 `CLAUDE.md` 뒤에 붙는다 [1].
- [사실] 작업 폴더 아래 하위 폴더의 CLAUDE.md는 시작 때가 아니라, Claude가 그 폴더의 파일을 읽거나 쓰거나 고칠 때 한 번 로드된다 [1].
- [사실] 확인법: 세션에서 `/context`를 실행하고 **Memory files** 목록을 본다. 하위 폴더 CLAUDE.md는 시작 때 로드되지 않으므로 이 목록에 없고, 로드되면 터미널에 `Loaded` 줄이 나온다 [1].
- [사실] "우선순위"라는 표현에 주의: 공식 문서는 "덮어쓰기"가 아니라 "이어 붙이기 + 순서"로 설명한다. 사용자 규칙과 프로젝트 규칙이 충돌하면 Claude가 어느 쪽이든 따를 수 있다고 한다(`.claude/rules/` 항목) [1].
- [사실] `--add-dir`로 추가한 폴더의 CLAUDE.md는 기본으로 로드되지 않는다. 환경 변수 `CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1`을 켜야 한다 [1].
- [사실] 조직 관리형 CLAUDE.md는 개발자가 `claudeMdExcludes`로 제외할 수 없다. 반면 대형 저장소에서 남의 CLAUDE.md가 섞이면 `claudeMdExcludes`로 개인 설정에서 건너뛸 수 있다 [1].
- [사실] 블록 수준 HTML 주석(`<!-- 메모 -->`)은 컨텍스트에 주입되기 전에 제거된다. 사람이 읽을 관리자 메모를 토큰 소비 없이 남길 때 쓴다(코드 블록 안 주석은 유지) [1].
- 신뢰도: 높음 (단일 공식 문서 [1], 일부는 [8]과 일치). 위치 표는 입문자 글에서 "개인용/프로젝트용/하위 폴더" 3가지만 강조해도 충분하다는 것은 [해석].

### Q3. 무엇을 적고 무엇을 적지 말아야 하나

- [사실] 권장 길이: CLAUDE.md 파일당 200줄 미만을 목표로 한다. 길수록 컨텍스트를 더 쓰고 준수율이 떨어진다 [1]. 200줄을 넘는 지침 파일이 있으면 시작 때와 `/status`에서 경고가 나온다 [1].

- [사실] 절차(여러 단계)이거나 코드베이스 일부에만 해당하는 내용은 스킬이나 경로 한정 규칙으로 옮기라고 안내한다 [1].
- [사실] 대문자 `IMPORTANT` 같은 강조는 요즘 모델에는 필요 없고, 오히려 규칙을 과적용하게 만든다고 한다. 계속 어기면 파일이 너무 길어 묻힌 것이거나, 예외 없는 규칙이라 훅·deny 규칙이 맞다 [2].
- [사실] 구조: 마크다운 제목과 글머리표로 묶는다. 빽빽한 문단보다 따르기 쉽다 [1].
- [사실] 공식 모범 사례의 짧은 예 (Commands / Conventions / Gotchas 3구역, 7줄 안팎) [2]. 글에는 원문을 길게 옮기지 말고 구성 방식만 소개하는 편이 안전하다.
- 좋은 예·나쁜 예 (공식 예의 요지를 입문자용으로 풀어 쓴 것):

  - 좋은 예: "테스트 한 파일 실행: `명령`", "`src/legacy/`는 쓰이고 있지만 새 코드에서 그 방식을 따라 하지 않는다", "통합 테스트는 `DATABASE_URL` 설정이 필요하다" [2]

### Q4. `/init`과 시작 순서

- [사실] `/init`은 코드베이스를 분석해 빌드 명령, 테스트 방법, 발견한 프로젝트 관례가 담긴 CLAUDE.md를 만든다. 이미 있으면 덮어쓰지 않고 개선안을 낸다 [1].
- [사실] 명령 목록의 설명: "Initialize project with a CLAUDE.md guide." 환경 변수 `CLAUDE_CODE_NEW_INIT=1`을 설정하면 스킬·훅·개인 메모리 파일까지 안내하는 대화형 흐름이 된다 [5].
- [사실] 신규 init 흐름(`CLAUDE_CODE_NEW_INIT=1`): 설정할 산출물(CLAUDE.md, 스킬, 훅)을 묻고, 서브에이전트로 코드베이스를 탐색하고, 후속 질문으로 빈칸을 채운 뒤, 파일을 쓰기 전에 검토 가능한 제안을 보여 준다. 변수는 `/init` 실행 방식만 바꾸므로 켜 둬도 된다. 개인 옵션을 고르면 `CLAUDE.local.md` 생성과 .gitignore 처리를 대신 해 준다 [1].
- [사실] `/init`은 다른 도구의 지침도 흡수한다: `.cursor/rules/`·`.cursorrules`, `.github/copilot-instructions.md`. 신규 init 흐름에서는 `AGENTS.md`, `.devin/rules/`, `.windsurf/rules/`, `.clinerules`도 포함한다 [1]. `/import`는 다른 코딩 에이전트의 설정을 가져온다 [1].
- [사실] 공식 명령 문서의 "저장소에서의 첫 세션" 흐름: `/init`으로 시작용 CLAUDE.md 생성 → `/memory`로 다듬기 → `/mcp`로 서버 설정 → 필요한 서브에이전트 요청 → `/permissions`로 승인 규칙 설정 [5].
- [사실] 모범 사례 문서: "`/init`이 시작 버전을 만들고, 거기서부터의 일은 주로 줄을 지우는 것"이라고 한다 [2].
- [해석] 입문자용 단계 제안 (공식 흐름 [1][2][5]을 합친 것):
  1. 프로젝트 폴더에서 `claude` 실행
  2. `/init` 실행 (필요하면 `CLAUDE_CODE_NEW_INIT=1`)
  3. 생성된 초안을 `/memory`로 열어 읽기
  4. Claude가 코드만 봐도 알 만한 줄(폴더 설명 등)은 지우고, 모호한 줄은 구체화
  5. 코드에 없는 정보(실행 명령 함정, 팀 결정) 3~5줄 추가
  6. 새 세션에서 `/context`로 Memory files 목록에 뜨는지 확인
  7. 같은 실수가 반복될 때만 한 줄씩 추가(공식 기준 [1])
- 신뢰도: 높음. 단, `/init`이 실제로 만드는 결과물의 모양·줄 수는 환경마다 달라 직접 실행한 경험이 필요하다.

### Q5. 관련 기능과 최신 변경

- [사실] **@ 가져오기**: CLAUDE.md 안에서 `@경로`로 다른 파일을 가져온다. 상대 경로는 "가져오는 파일" 기준(작업 폴더 기준이 아님). 재귀 가져오기는 최대 4단계다. 공백이 든 경로는 공백 앞에 역슬래시. 코드 스팬·코드 블록 안은 가져오기로 처리하지 않으므로 경로를 그냥 언급만 하려면 백틱으로 감싼다(`` `@README` ``) [1].
- [사실] 가져오기는 정리에는 도움되지만 컨텍스트 비용을 줄이지 않는다. 가져온 파일이 함께 로드되기 때문이다 [1].
- [사실] 프로젝트 밖 경로(예: 홈 폴더)를 가져오면 처음 한 번 승인 대화상자가 뜬다. 거절하면 비활성 상태로 남는다 [1].
- [사실] **`.claude/rules/`**: 주제별 마크다운 파일(`testing.md` 등)을 두면 재귀적으로 모두 발견된다. `paths` 프런트매터가 없는 규칙은 시작 때 `.claude/CLAUDE.md`와 같은 우선순위로 로드되고, `paths`(glob)가 있으면 해당 파일을 다룰 때만 로드된다. 규칙 파일이 읽는 프런트매터 필드는 `paths` 하나뿐이다 [1]. 개인 규칙은 `~/.claude/rules/`에 둔다 [1].
- [사실] **`/memory`**: CLAUDE.md·CLAUDE.local.md 등 메모리 파일 위치를 사용자·프로젝트 범위에서 나열하고(아직 없는 파일도 표시), 선택하면 편집기로 연다. 없는 파일을 고르면 먼저 만든다. 자동 메모리 켜기·끄기와 자동 메모리 폴더 열기도 여기서 한다 [1].
- [사실, 최신 변경] 대화에서 "항상 pnpm을 써, npm 말고" 같은 말을 하면 Claude는 자동 메모리에 저장한다. CLAUDE.md에 넣으려면 "이걸 CLAUDE.md에 추가해"라고 직접 말하거나 `/memory`로 편집하라고 문서가 안내한다 [1].
- [사실, 최신 변경] **`#` 단축키**: 현재 공식 "빠른 명령" 표에는 `/`(명령·스킬), `!`(셸 모드), `@`(파일 경로), `:`(이모지)만 있고 `#`은 없다 [6]. 메모리 문서의 추가 방법에도 `#` 언급이 없다 [1]. GitHub 이슈 #14868(2025-12-20, v2.0.74에서 `#` 단축키가 CLAUDE.md에 저장되지 않는다는 보고)에서 한 커뮤니티 이용자가 "2.0.70에서 제거됐다"고 changelog를 인용해 말했다. 하지만 Anthropic 직원의 답은 없었고, 나는 해당 changelog 항목을 직접 열어 확인하지 못했다 [9]. 한편 검색 결과에는 이전 docs.anthropic.com 메모리 문서가 `#`로 메모리를 추가한다고 안내했다는 요약이 있었으나 이 문서의 원문을 열어 보지는 못했다. 결론: "`#`로 빠르게 추가"는 옛 자료의 내용이며 현재는 쓰지 않는 방법으로 다루는 것이 안전하다.
- [사실] **`/doctor`와 `/doctor prompt-audit`**: `/doctor`는 설치·설정·확장·CLAUDE.md 문제를 진단하고 고칠 안을 제안한다(확인 후 적용). 체크인한 CLAUDE.md에서 코드에서 파생 가능한 내용의 삭제를 제안한다 [1][5]. `prompt-audit`는 옛 모델용으로 쓰인 지침, 없는 파일·명령 참조, 서로 모순되는 파일을 찾아 보고서로 낸다. 사용자가 요청하기 전에는 파일을 바꾸지 않는다. v2.1.283 이상이 필요하다 [1].
- [사실] **AGENTS.md**: v2.1.277 이상에서 AGENTS.md만 있는 저장소는 그대로 읽는다. CLAUDE.md(또는 CLAUDE.local.md)가 작업 폴더나 상위에 있으면 CLAUDE.md만 읽는다. 둘을 같이 쓰려면 CLAUDE.md에 `@AGENTS.md`를 적는다. Windows에서는 심볼릭 링크보다 `@AGENTS.md` 가져오기가 안전하다 [1].
- [사실] 그 밖의 최근 변경(문서에 버전이 명시된 것): 경로 한정·하위 폴더 규칙 파일의 크기 한도는 v2.1.309부터 적용 [1]. `/memory`는 v2.1.216부터 GUI 편집기를 열어 둔 채 세션을 계속 쓸 수 있다 [1]. 이 숫자들은 글에서는 "최신 버전 기준"이라고만 쓰는 것이 안전하다(이전 노트 권고와 동일).
- 신뢰도: 높음. `#` 단축키 제거 이력은 근거 약함(아래 4절).

### Q6. 자주 하는 실수와 한계

- [사실] 강제 규칙이 아니다. "특정 행동을 무조건 막으려면" PreToolUse 훅, 또는 deny 규칙 같은 설정을 쓴다 [1][2].

- [사실] 길면 효과가 약해진다(200줄 이상 권장하지 않음). 줄마다 매 작업에서 Claude의 주의를 조금씩 쓰기 때문이다 [1][2].
- [사실] 서로 모순되는 규칙이 있으면 Claude가 임의로 하나를 고를 수 있다. CLAUDE.md, 하위 폴더 CLAUDE.md, `.claude/rules/`를 주기적으로 점검한다 [1].
- [사실] 지침이 Claude Code의 내장 지침과 겹치면 충돌할 수 있다. 커밋·PR 규칙을 CLAUDE.md에 쓸 때는 내장 규칙을 `includeGitInstructions`로 끄고 `attribution`으로 문구를 정한다 [1].
- [사실] 하위 폴더 CLAUDE.md나 온디맨드 규칙 파일이 크기 한도를 넘으면 앞부분만 전달되고 나머지는 Claude가 Read로 읽기 전에는 컨텍스트에 없다. 한도는 200K 컨텍스트 창 기준 40,000자, 1M 창에서는 모델에 따라 200,000자 또는 150,000자다. 시작 때 로드되는 파일은 4 MiB 이하여야 한다(넘으면 통째로 건너뜀) [1].
- [사실] `/compact` 뒤에도 프로젝트 루트 CLAUDE.md는 디스크에서 다시 읽어 주입된다. 대화로만 준 지시는 사라질 수 있으니 오래 갈 지시는 CLAUDE.md에 넣는다 [1].
- [사실] **서브에이전트와의 관계**: 일반(비포크) 서브에이전트는 메인 대화가 로드한 CLAUDE.md 계층 전체(사용자 CLAUDE.md, 프로젝트 규칙, CLAUDE.local.md, 관리형 파일, AGENTS.md)를 초기 컨텍스트로 받는다. 단 내장 Explore·Plan은 건너뛴다(빠르고 싸게 하려고). 서브에이전트 정의에 `omitClaudeMd`(v2.1.271 이상)를 쓰면 관리형만 받는다. Explore·Plan 등도 하위 폴더 CLAUDE.md와 경로 한정 규칙은 그 폴더 파일을 다룰 때 로드된다. 반드시 전달해야 할 규칙은 위임 프롬프트에 다시 적는다. 메인 대화의 자동 메모리는 서브에이전트에 로드되지 않는다 [3]. 이전 노트의 "대부분의 서브에이전트가 CLAUDE.md를 로드(Explore·Plan 제외)"와 일치한다.
- [사실] 민감정보: 공식 문서에 "CLAUDE.md에 비밀번호를 넣지 마라"는 직접 문구는 찾지 못했다. 다만 프로젝트 CLAUDE.md는 버전 관리로 팀과 공유되는 파일이라 설명되고 [1], 개인용 값은 `.gitignore`한 `CLAUDE.local.md`에 두라고 안내한다 [1]. `.env` 같은 비밀 파일은 deny 규칙으로 막는 것이 공식 예시다 [2]. 비밀번호·API 키를 CLAUDE.md에 쓰지 말라는 권고는 [해석]이다. 근거: 공유 파일이고 컨텍스트로 모델에 전달되는 파일이기 때문.
- 신뢰도: 높음 (서브에이전트는 문서 3, 앞선 노트와 일치). 민감정보는 직접 문구 없음(해석).

### Q7. 자동 메모리와 CLAUDE.md의 차이

| | CLAUDE.md | 자동 메모리 |
| :-- | :-- | :-- |

- [사실] 주제별 파일은 시작 때 로드되지 않고 필요할 때 Claude가 읽는다. 전부 평문 마크다운이라 열어 보고 고치거나 지울 수 있다 [1].
- [사실] 구분 팁: 내가 "무엇을 지켜라"고 정하는 것은 CLAUDE.md, Claude가 내 교정에서 스스로 배운 것은 자동 메모리. CLAUDE.md는 팀과 공유될 수 있지만 자동 메모리는 내 컴퓨터에만 있다 [1].
- 신뢰도: 높음 (단일 공식 문서 [1], 앞선 노트와 일치)

## 4. 상충하거나 불확실한 내용

- **`#` 단축키**: 공식 현재 문서에는 없고 [1][6], 커뮤니티 이슈에서 "v2.0.70에서 제거"라는 주장이 있으나(작성자 의견, 직접 확인 못함) [9], 검색 결과 요약에는 구 문서가 안내했다는 기록이 있다. 정확한 제거 시점은 근거 약함. 글에서는 "예전 자료에 나오는 방법이며 지금 공식 문서에는 없다"까지만 쓴다. changelog는 앞 100,000자만 읽었고 2.0.70 구간은 포함되지 않았다 [7].
- **"우선순위"라는 표현**: 공식 문서는 덮어쓰기가 아니라 이어 붙이기·순서(구체적일수록 나중에 읽힘)로 설명하고, 충돌 시 어느 쪽을 따를지 보장하지 않는다 [1]. 블로그 글에서 "A가 B를 이긴다"고 쓰면 부정확하다.
- 서브에이전트 문서 중 `omitClaudeMd`, 내장 에이전트별 상세는 앞 100,000자만 읽었다. 뒤 16,349자는 읽지 못했다 [3].
- 시작 때 로드되는 파일에 파일별 길이 경고가 뜨는 정확한 줄 수 기준은 "권장 길이 초과 시"로만 나와 있고 그 기준값(200)이 같은 값인지는 문서가 명시하지 않았다. 글에서는 "200줄 안팎"으로 표현한다.
- 모범 사례 문서가 내장 모델·`effort` 등 모델 이름(Opus 5.5 등)을 언급하지만 이번 글 주제와 무관해 다루지 않았다.

**독자 FAQ 후보**
- Q. 꼭 써야 하나요? → 안 써도 동작한다. 같은 실수를 두 번 교정하거나 같은 설명을 반복하게 될 때 쓰면 된다 [1][2].
- Q. 파일 이름·위치는? → 프로젝트 루트의 `CLAUDE.md`. 나만 쓸 설정은 `CLAUDE.local.md`(.gitignore) 또는 `~/.claude/CLAUDE.md` [1].
- Q. 잘 적용되는지 어떻게 확인? → 세션에서 `/context`의 Memory files 목록 [1].
- Q. 쓴 대로 안 하는데요? → 구체적으로 고치고, 모순을 점검하고, 길면 줄이고, 꼭 지켜야 하면 훅·deny 규칙으로 [1][2].
- Q. 서브에이전트도 읽나요? → 대부분 읽는다(Explore·Plan 제외) [3].
- Q. 자동 메모리와 뭐가 다른가요? → 내가 쓰는 규칙 vs Claude가 스스로 적는 메모 [1].
- Q. `#`으로 추가한다던데? → 옛 자료의 방법. 지금은 "CLAUDE.md에 추가해 줘"라고 말하거나 `/memory` [1][6].

**장단점·비교 포인트**
- 장점: 반복 설명 감소, 팀 공유 가능, 파일 한 개로 시작 가능 [1].
- 단점·한계: 강제력 없음, 길면 효과 약화, 모순 위험, 유지보수(옛 지침이 남음) 필요 [1][2].
- 비교: CLAUDE.md(항상 필요한 지식) / 경로 한정 규칙(일부 파일에만) / 스킬(가끔 필요한 절차) / 훅·deny(예외 없는 강제) [1][2].

**복사해 쓸 수 있는 예시 [해석]** — 아래는 내가 공식 지침 [1][2]의 원칙에 맞춰 만든 가상의 입문자용 예시다. 공식 문서의 예가 아니며, 명령과 파일 이름은 독자의 프로젝트에 맞게 바꿔야 한다.

예시 A (작은 웹페이지 연습 프로젝트를 가정한 CLAUDE.md, 약 12줄):

```markdown
# 프로젝트
- 개인 연습용 할 일 목록 웹페이지 (HTML, CSS, JavaScript만 사용)
```

**참고 사례 (필자 경험이 아님)**
- [저장소] 이 저장소의 루트 `CLAUDE.md`는 저장소 개요, 명령, 구조 설명, 에이전트 파일 작성 규칙을 담고 있고 앞선 노트에서도 사례로 썼다. 다만 이 파일은 AI 에이전트가 작성·수정에 관여했는지, 필자가 직접 썼는지 이번에 확인하지 않았으므로 "필자가 이렇게 썼다"고 단정하지 않는다. 사례로 쓸 때는 "한 저장소의 CLAUDE.md 예"라고 소개한다. 또 이 파일은 구조를 자세히 적는 편이라 공식의 "코드에서 알 수 있는 구조 설명은 줄여라" 권고와 거리가 있을 수 있다 [2]. 비교해서 쓰려면 필자가 직접 판단한다. 줄 수는 확인하지 않았다.

**경험 보강 필요 후보** (리서치로는 채울 수 없음. 필자가 실제로 한 경우에만 쓸 것)
1. `/init`을 처음 실행했을 때 나온 초안의 모습(줄 수, 어떤 항목이 들어 있었는지), 그중 지운 부분과 남긴 부분
2. CLAUDE.md를 쓰기 전/후에 같은 요청을 했을 때 달라진 점(예: 매번 말하던 것을 더 이상 말하지 않아도 된 순간)
3. 처음 쓴 규칙이 모호해서 안 지켜졌고, 구체적으로 바꾸자 달라진 사례
4. `/context`로 Memory files 목록을 확인한 화면
5. 길어졌다가 줄인 경험, 모순된 규칙 때문에 헷갈렸던 경험
6. 자동 메모리가 "Saved N memories"로 저장한 내용을 `/memory`에서 열어 본 소감
7. 서브에이전트를 쓸 때 CLAUDE.md가 적용된 것을 확인한 사례(앞선 서브에이전트 글과 연결)
8. `CLAUDE.local.md`나 `~/.claude/CLAUDE.md`를 따로 만들어 쓴 이유
9. 막혔던 점(파일이 인식되지 않은 이유, 위치를 잘못 둔 실수 등)

## 용어 설명

- **CLAUDE.md**: Claude가 세션을 시작할 때마다 읽는 내 지침 메모 파일. 평문으로 쓴다.
- **컨텍스트(context)**: Claude가 한 번에 보고 있는 대화·파일의 분량. 지침이 길수록 여기서 더 많은 자리를 차지한다.
- **세션**: `claude`를 켜서 끄기까지의 한 번의 대화. 새 세션은 이전 대화를 기억하지 못한다.
- **마크다운(markdown)**: `#` 제목, `-` 목록 같은 간단한 기호로 서식을 주는 텍스트 형식.
- **`/init`**: 프로젝트를 분석해 CLAUDE.md 초안을 만들어 주는 명령.
- **`/memory`**: CLAUDE.md 등 메모리 파일을 열어 편집하고 자동 메모리를 켜고 끄는 명령.
- **`/context`**: 지금 어떤 파일(CLAUDE.md 포함)이 컨텍스트에 올라와 있는지 보는 명령.
- **자동 메모리(auto memory)**: Claude가 내 교정과 선호를 보고 스스로 적어 두는 메모. 내 컴퓨터에만 저장된다.
- **임포트(`@경로`)**: CLAUDE.md 안에서 다른 파일 내용을 함께 읽게 하는 문법.
- **`.claude/rules/`**: 규칙을 주제별 파일로 나눠 두는 폴더. 특정 파일을 다룰 때만 로드되게 할 수도 있다.
- **프런트매터(frontmatter)**: 마크다운 파일 맨 위 `---` 사이에 적는 설정 부분.
- **glob 패턴**: `**/*.css`처럼 `*` 기호로 여러 파일을 한꺼번에 가리키는 표기.
- **훅(hook)**: 특정 시점에 반드시 실행되는 자동 명령. CLAUDE.md와 달리 강제된다.
- **deny 규칙**: 특정 파일·명령을 아예 못 쓰게 막는 권한 설정.
- **서브에이전트**: 메인 대화와 따로 일하고 결과만 돌려주는 보조 AI.
- **워크트리(worktree)**: 같은 git 저장소의 작업 폴더를 여러 개로 나눠 쓰는 기능.
- **.gitignore**: git이 추적하지 않을 파일을 적는 목록. 개인용 파일이 공유되지 않게 한다.
- **AGENTS.md**: 여러 AI 코딩 도구가 함께 읽는 지침 파일 형식. Claude Code도 읽는다.
