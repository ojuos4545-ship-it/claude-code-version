🛠️ 시작하기 전에 - CLAUDE.md는 왜 필요할까요?


Claude Code 세션은 매번 새 컨텍스트로 시작합니다.

Step 1. 파일은 어디에 만들까요? - 위치 고르기와 /init 초안


처음 시작할 때 가장 많이 헷갈리는 부분이 파일 위치입니다.

범위에 따라 놓을 곳이 달라요.


범위 위치 누구에게 적용되나
프로젝트 ./CLAUDE.md 또는 ./.claude/CLAUDE.md 팀 (버전 관리에 포함)
사용자 ~/.claude/CLAUDE.md 나, 모든 프로젝트
로컬 ./CLAUDE.local.md 나, 현재 프로젝트

아래 순서대로 차근차근 따라와 주세요.

3. 만들어진 파일을 열어 봅니다. (/memory를 입력하면 메모리 파일 목록이 나오고, 거기서 편집기로 열 수 있어요)

4. 초안을 그대로 두지 말고 다음 단계에서 줄을 덜어 냅니다.

Step 2. 무엇을 적고 무엇을 지울까요? - 제 CLAUDE.md를 예로


기본이 끝났다면 이제 내용을 채울 차례입니다.

공식 문서의 원칙은 단순해요. Claude가 코드만 봐서는 알 수 없는 것만 적으라는 겁니다.


사진 04


• 확인 명령: 테스트, 린트, 파일 하나만 돌리는 법

• 오해하기 쉬운 곳: 남아 있지만 새 코드엔 쓰면 안 되는 옛 패턴 같은 것

• 저장소 밖 결정: 코드에 나오지 않는 팀의 약속이나 배포 방식

• 두 번 교정한 것: 같은 말을 두 번 했다면 적어 둘 후보


반대로 줄이는 쪽도 정해져 있습니다.

아키텍처나 파일 구조 설명은 Claude가 저장소를 직접 읽으니 거기 없는 것만 남기라는 안내가 있어요.

문장은 검증할 수 있게 쓰는 편이 좋습니다.


이렇게 쓰면 이렇게는 피하세요
2칸 들여쓰기를 쓴다 코드를 잘 정리한다
커밋 전에 npm test를 실행한다 테스트를 열심히 돌린다


참고로 IMPORTANT 같은 강조어를 덧붙여도 해결되지 않는다고 합니다. 평이한 문장이면 충분하고, 강조가 쌓이면 오히려 규칙을 과하게 적용할 수 있다는 설명이에요.


제가 쓰는 파일은 이렇게 생겼어요


저는 제 저장소에 CLAUDE.md를 두고 쓰는데요.

6개 섹션, 67줄 정도로 공식 권장인 200줄 미만 안에 들어옵니다.

담은 내용은 다섯 가지입니다.


사진 05


• 서버 실행과 테스트 명령

• 함정 (예: 설정에 -q가 이미 있어서 또 주면 요약 줄이 사라진다는 점)

• 하지 말 것과 그 이유

• 폴더와 계층 구조

• 에이전트 파일을 쓸 때의 규칙


가장 공들인 건 "하지 말 것 + 이유" 줄입니다.

innerHTML은 쓰지 않는다고 적고, 토큰이 localStorage에 있어서 XSS가 곧 토큰 탈취라는 이유를 붙였어요.

확인 창도 confirm() 대신 화면 안 askConfirm을 쓰라고 하고, iframe에서는 confirm()이 항상 false라는 이유를 함께 적었습니다.


이유까지 적어 두면 코드만 봐서는 알 수 없는 사정이 전해지고, 규칙을 어길 때 되돌리는 수고도 줄어들 거라고 생각했어요.


솔직히 다시 읽어 보니 고칠 곳도 보입니다.

구조를 설명한 줄에는 저장소를 읽으면 알 수 있는 내용이 섞여 있어서, 공식 기준으로는 줄일 후보예요.

한 줄이 지나치게 긴 곳도 있습니다.


📌 전문가 Tip: 여러분의 파일이 길어졌다면 /doctor가 코드에서 알 수 있는 내용을 덜어 내자고 제안해 줍니다. 함정이나 이유가 적힌 줄은 남기는 쪽이고요. 다만 /doctor prompt-audit은 v2.1.283 이상이 필요하니 버전을 먼저 확인하세요.



Step 3. 잘 읽히고 있을까요? - 확인하고 낡지 않게 관리하기


파일을 만들었다고 끝이 아닙니다.

Claude가 실제로 읽고 있는지부터 봐야죠.


1. 세션에서 /context를 실행합니다.

2. Memory files 목록에 내 파일이 있는지 확인합니다. (목록에 없으면 Claude가 볼 수 없어요)

3. 하위 폴더의 CLAUDE.md는 시작할 때 로드되지 않아 목록에 안 보입니다. (그 폴더의 파일을 읽게 하면 터미널에 Loaded 줄이 나와요)


시간이 지나면 낡는다는 것


제가 겪은 일도 하나 말씀드릴게요.

서브에이전트 image-maker를 새로 만들었는데, CLAUDE.md의 에이전트 목록에 추가하는 걸 빠뜨렸습니다.

나중에야 알아채서 고쳤어요.


코드나 파일이 바뀌면 CLAUDE.md도 같이 고쳐야 낡지 않습니다.

없는 파일을 가리키는 줄이나 서로 모순되는 줄이 남으면, Claude도 헷갈릴 수 있으니까요.


CLAUDE.md의 한계 - 꼭 지켜야 하는 규칙은 어디에 둘까요?


CLAUDE.md는 강제 장치가 아니라 맥락을 전하는 파일입니다.

Claude가 읽고 따르려 하지만, 엄격하게 지켜진다는 보장은 없다고 공식 문서도 말해요.

그래서 목적에 맞는 곳에 나눠 두는 게 좋습니다.


수단 맞는 용도
CLAUDE.md 항상 알아야 할 사실과 선호
경로 한정 규칙 (.claude/rules/) 일부 파일에만 해당하는 규칙
스킬 여러 단계의 절차, 필요할 때만 읽기
훅 예외가 없어야 하는 규칙, 자동 실행

막힐 때 자주 묻는 질문


Q. 적었는데 안 지켜져요.

A. 순서대로 점검해 보세요. 로드 여부, 파일 위치, 지침의 구체성, 파일 간 상충, 그리고 Claude Code가 자체로 넣는 커밋·PR 지침과의 충돌입니다.


사진 07


Q. 얼마나 길게 써야 하나요?

A. 공식 권장은 파일당 200줄 미만입니다. 길수록 컨텍스트를 더 쓰고 준수율이 떨어질 수 있다고 해요.


Q. 다른 파일을 가져와 쓸 수 있나요?

A. @경로 문법으로 가능합니다. 다만 정리에는 도움이 되어도, 가져온 파일이 함께 로드되니 컨텍스트 비용은 줄지 않아요.


Q. 대화 중에 말한 건 유지되나요?

A. 대화로만 준 지침은 /compact 뒤에 사라질 수 있습니다. 오래 가져가야 한다면 CLAUDE.md에 적어 두세요.


Q. 저장소에 AGENTS.md만 있는데요?

A. CLAUDE.md가 없고 AGENTS.md만 있으면 AGENTS.md를 읽습니다. 이 동작은 v2.1.277 이상에서 확인되는 내용이라 버전을 확인하세요.
