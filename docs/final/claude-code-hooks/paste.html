1. 클로드 코드 훅이 뭐예요? - CLAUDE.md와 무엇이 다를까요?


CLAUDE.md는 Claude가 읽고 참고하는 메모입니다.

읽은 뒤 따를지 말지는 Claude(모델)가 판단하죠. 그래서 대부분 지키지만, 매번 지킨다는 보장은 없습니다.


훅은 다릅니다.

Claude가 아니라 클로드 코드 프로그램이 직접 정해진 순간에 명령을 실행해요.

Claude가 규칙을 잊어버려도, 바빠서 넘어가려 해도 상관없습니다.


공식 모범 사례 문서도 이 둘을 나눠서 설명합니다.

"꼭 매번 일어나야 하는 일은 훅 같은 강제 장치로, CLAUDE.md는 지침용"이라는 거예요.


구분 CLAUDE.md 훅
누가 실행하나 Claude가 읽고 판단 클로드 코드가 매번 실행
잘 맞는 일 말투, 설명 방식, 선호 꼭 지킬 규칙, 반복 작업
적는 곳 CLAUDE.md 파일 settings.json 파일


【사진 02】 02_table_claude-md-vs-hook.png


그렇다고 모든 걸 훅으로 만들 필요는 없어요.

공식 문서는 단순한 취향까지 훅으로 만들었다면 오히려 지우라고 권합니다.

"이건 단 한 번도 예외가 없어야 해" 싶은 일만 훅으로 옮기는 것이 요령입니다.



2. Step 1. 위치와 구조 - 어디에, 어떻게 적을까요?


훅은 settings.json이라는 설정 파일에 적습니다.

어느 위치의 파일에 적느냐에 따라 적용 범위가 달라져요.


• ~/.claude/settings.json: 내 컴퓨터의 모든 프로젝트에 적용 (~는 내 홈 폴더)

• .claude/settings.json: 이 프로젝트에만 적용. 저장소에 올리면 팀원과 함께 씀

• .claude/settings.local.json: 이 프로젝트에서 나만 씀. 저장소에 올리지 않음


【사진 03】 03_card_locations.png


알림처럼 어디서나 쓰고 싶은 건 첫째 파일에, 프로젝트 규칙은 둘째 파일에 두면 됩니다.

여러 파일에 훅이 있으면 서로 덮어쓰지 않고 모두 합쳐져요.


적는 모양은 늘 같습니다. "언제(이벤트) → 어떤 경우에(matcher) → 무엇을 실행(command)" 순서예요.


{

  "hooks": {

    "이벤트 이름": [

      {

        "matcher": "어떤 도구일 때만",

        "hooks": [

          { "type": "command", "command": "실행할 명령" }

        ]

      }

    ]

  }

}


matcher는 "이 도구를 쓸 때만"처럼 범위를 좁히는 칸입니다.

"Edit|Write"라고 쓰면 파일을 고치는(Edit) 도구와 새로 쓰는(Write) 도구에만 반응해요. 비워 두면 전부에 반응합니다.


조사일 기준으로 이벤트는 33가지나 됩니다.

처음에는 아래 몇 가지만 알아도 충분해요.


이벤트 언제 실행되나
SessionStart 클로드 코드를 켜거나 이어서 시작할 때
UserPromptSubmit 내가 질문을 보낸 직후, Claude가 읽기 전
PreToolUse Claude가 도구(파일 수정, 명령 실행 등)를 쓰기 직전. 여기서 막을 수 있음
PostToolUse 도구를 쓴 직후. 이미 끝난 일이라 되돌리지는 못함
Notification 클로드 코드가 내 입력이나 허락을 기다리며 알림을 보낼 때
Stop Claude가 답을 마쳤을 때


【사진 04】 04_diagram_events.png


📌 전문가 Tip: 이미 settings.json에 "hooks"가 있다면 통째로 바꾸지 마세요. 새 이벤트 이름을 그 안에 나란히 추가해야 기존 훅이 지워지지 않습니다. 그리고 JSON에는 마지막 쉼표나 주석을 쓸 수 없어요.



3. Step 2. 첫 훅 만들기 - 알림 훅 따라 하기


첫 훅으로는 공식 가이드가 맨 처음 소개하는 알림 훅이 좋습니다.

Claude가 내 허락을 기다릴 때 컴퓨터 알림을 띄워 주니, 터미널만 지켜보고 있을 필요가 없어져요.

위험한 일을 하지 않는 훅이라 연습용으로도 안성맞춤입니다.


아래 순서대로 차근차근 따라와 주세요.


1. 설정 파일 열기: ~/.claude/settings.json을 엽니다. (파일이 없으면 새로 만들면 됩니다.)

2. 훅 붙여넣기: 아래 내용을 넣습니다. macOS용 예시예요. (이미 다른 설정이 있다면 맨 바깥 { } 안에 "hooks" 부분만 추가합니다.)

3. 목록에서 확인: 클로드 코드에서 /hooks를 입력합니다. Notification 아래에 방금 넣은 훅이 보이면 성공이에요. (이 화면은 보기 전용이라 여기서 고치지는 못합니다.)

4. 시험하기: Claude에게 허락이 필요한 일을 시킨 뒤 다른 창으로 가 있어 보세요. 잠시 뒤 알림이 뜹니다. (공식 가이드는 먼저 Shift+Tab을 눌러 아래 상태 줄에 manual mode on이 보이게 하라고 안내해요. 허락을 묻는 상태여야 알림이 울릴 일이 생기니까요.)


{

  "hooks": {

    "Notification": [

      {

        "matcher": "",

        "hooks": [

          {

            "type": "command",

            "command": "osascript -e 'display notification \"Claude Code needs your attention\" with title \"Claude Code\"'"

          }

        ]

      }

    ]

  }

}


【사진 05】 05_diagram_first-hook.png


Linux는 notify-send 'Claude Code' 'Claude Code needs your attention'처럼 명령 부분만 바꾸면 됩니다.

Windows용 PowerShell 명령도 공식 가이드에 함께 나와 있어요.


macOS에서 알림이 안 뜬다면 '스크립트 편집기' 앱에 알림 권한이 없는 경우가 많습니다.

공식 가이드는 터미널에서 osascript -e 'display notification "test"'를 한 번 실행한 뒤, 시스템 설정 > 알림에서 스크립트 편집기를 허용하라고 안내해요.


저도 직접 시험해 봤습니다.

다만 제 실습 환경은 화면이 없는 클라우드 컴퓨터라, 알림 대신 "언제 실행됐는지"를 파일에 한 줄씩 적게 바꿨어요.

Notification과 Stop(답을 마쳤을 때) 두 이벤트에 같은 기록 명령을 걸고, 간단한 질문을 하나 보냈습니다.


• Stop: 답이 끝난 순간 기록이 딱 한 줄 남았습니다.

• Notification: 아무것도 남지 않았어요. 제가 허락할 일 없이 바로 끝난 질문이었으니, 알림 보낼 일도 없었던 거죠.


'이벤트 = 정해진 순간'이라는 말이 이런 뜻이었습니다.

그 순간이 오지 않으면 훅도 실행되지 않아요.



4. Step 3. 정리하고 막기 - 자주 쓰는 훅 두 가지


기본이 끝났다면 이제 프로젝트에서 바로 쓸 만한 훅을 만들어 볼 차례입니다.

이번에는 프로젝트 폴더의 .claude/settings.json에 적어요.


4-1. 고친 파일을 자동으로 정리하기


Claude가 파일을 고칠 때마다 코드 정리 도구(Prettier)가 모양을 맞춰 주는 훅입니다.

"따옴표는 큰따옴표로" 같은 규칙을 Claude가 기억할 필요가 없어져요.


{

  "hooks": {

    "PostToolUse": [

      {

        "matcher": "Edit|Write",

        "hooks": [

          {

            "type": "command",

            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"

          }

        ]

      }

    ]

  }

}


훅이 실행되면 클로드 코드가 "방금 고친 파일은 어디인지" 같은 정보를 넘겨줍니다.

jq가 거기서 파일 경로만 꺼내고, Prettier가 그 파일을 정리하는 구조예요.

(jq는 macOS면 brew install jq, Ubuntu면 apt-get install jq로 설치합니다. npx를 쓰려면 Node.js도 있어야 해요.)


실제로 비교해 봤습니다.

두 연습 프로젝트에 똑같이 "app.js 맨 아래에 console.log('ready'); 한 줄을 작은따옴표 그대로 추가해 줘"라고 요청했어요.


훅 없음 훅 있음
추가된 줄 console.log('ready'); console.log("ready");
Claude의 반응 "다른 줄은 큰따옴표라 이 줄만 스타일이 다르다"고 알려 줌 파일이 바뀐 것을 알아차리고 어떻게 할지 되물음


훅이 있는 쪽은 Claude가 부탁대로 작은따옴표로 적었는데도, 저장된 파일은 큰따옴표로 바뀌어 있었어요.

Claude의 판단과 상관없이 정리 규칙이 이긴 겁니다.


흥미로운 건 그다음이었어요.

Claude가 "훅이 걸리지 않는 셸 명령으로 고치면 작은따옴표를 남길 수 있지만, 프로젝트 규칙을 일부러 피하는 것이라 먼저 확인받겠다"고 답했습니다.

이 훅은 Edit·Write 도구만 지켜본다는 뜻이기도 해요. 공식 문서도 Claude가 셸 명령으로 파일을 바꿀 수 있다는 점을 따로 짚습니다.


4-2. 중요한 파일 수정 막기


이번에는 .env(비밀 키 같은 설정값을 두는 파일)처럼 건드리면 안 되는 파일을 지키는 훅입니다.

조금 길지만, 공식 가이드의 예시를 그대로 쓰시면 돼요.


먼저 .claude/hooks/protect-files.sh 파일을 만들어 아래 내용을 넣습니다.


#!/bin/bash

# protect-files.sh


INPUT=$(cat)

FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')


# Normalize Windows backslash separators so the patterns below match

FILE_PATH="${FILE_PATH//\\//}"


PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/")


for pattern in "${PROTECTED_PATTERNS[@]}"; do

  if [[ "$FILE_PATH" == *"$pattern"* ]]; then

    echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2

    exit 2

  fi

done


exit 0


고치려는 파일 경로에 .env, package-lock.json, .git/가 들어 있으면 이유를 남기고 exit 2로 끝나는 스크립트예요.

스크립트가 끝날 때 남기는 숫자(종료 코드)가 클로드 코드에게 결과를 알려 줍니다.

exit 0은 "문제없음", exit 2는 "막아라"라는 신호예요.


그다음 이 파일에 실행 권한을 주고(macOS·Linux), 설정에 등록합니다.


chmod +x .claude/hooks/protect-files.sh


{

  "hooks": {

    "PreToolUse": [

      {

        "matcher": "Edit|Write",

        "hooks": [

          {

            "type": "command",

            "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh"

          }

        ]

      }

    ]

  }

}


$CLAUDE_PROJECT_DIR는 프로젝트 폴더 위치를 가리키는 이름표라, 어느 폴더에서 실행해도 스크립트를 찾을 수 있어요.


【사진 06】 06_card_exit-codes.png


등록하기 전에 스크립트만 따로 시험해 볼 수도 있습니다.

가짜 정보를 넣어 실행해 보니, .env를 넣었을 때는 Blocked: 문장과 함께 2가 나왔고 app.js를 넣었을 때는 0이 나왔어요.


echo '{"tool_name":"Edit","tool_input":{"file_path":".env"}}' | ./.claude/hooks/protect-files.sh

echo $?


이제 Claude에게 ".env 파일 맨 위에 주석 한 줄을 추가해 줘"라고 두 번 요청해 봤습니다.

두 번 모두 .env는 그대로였어요.


Claude의 답도 인상적이었습니다.

"보호 훅이 .env 수정을 막아서 추가하지 못했고, 셸 명령으로 우회하지 않았다"고 설명한 뒤, 직접 추가하거나 훅에서 예외로 두는 방법을 골라 달라고 했어요.

스크립트가 남긴 이유가 Claude에게 그대로 전달된 덕분입니다.


📌 전문가 Tip: 이 스크립트는 경로에 패턴 글자가 들어 있기만 해도 막습니다. 그래서 .env 패턴은 .env.example 같은 파일까지 막아요. 패턴은 꼭 필요한 것만 넣고, 막는 규칙 자체도 적게 유지하라는 공식 모범 사례의 조언을 기억해 두세요.



5. 안 될 때는 어떻게 하나요? - 흔한 실수와 보안 주의


"분명히 만들었는데 안 막혀요" 싶을 때가 있습니다.

흔한 원인은 아래 세 가지인데, 앞의 두 가지는 제가 일부러 틀리게 만들어 직접 확인해 봤어요.


1) 끝내는 숫자를 1로 썼어요


스크립트의 exit 2를 exit 1로만 바꿔 같은 요청을 두 번 해 봤습니다.

두 번 모두 .env에 주석이 추가됐어요.


기록을 보면 스크립트는 분명 실행됐고 Blocked:라는 문장까지 남겼습니다.

하지만 1은 '막아라'가 아니라 '오류가 났다'는 뜻이라, 작업은 그대로 진행된 거예요. 공식 문서도 정책을 강제하려면 exit 2를 쓰라고 못 박아 둡니다.


2) matcher를 소문자로 썼어요


"Edit|Write"를 "edit|write"로 바꿔 봤습니다.

이번에도 .env가 바뀌었고, 기록에는 스크립트가 실행된 흔적조차 없었어요. matcher는 대소문자를 구분하기 때문입니다.


3) 스크립트를 못 찾거나 실행하지 못해요


chmod +x를 빼먹었거나 경로가 틀린 경우입니다.

절대 경로나 $CLAUDE_PROJECT_DIR를 쓰고, 위에서처럼 가짜 정보를 넣어 직접 실행해 보면 대부분 원인이 보여요.


【사진 07】 07_table_experiments.png


확인하는 방법도 정리해 둘게요.


• 목록 보기: /hooks에서 내가 넣은 이벤트 아래에 훅이 있는지 봅니다.

• 진행 기록 보기: Ctrl+O를 누르면 훅이 막았는지, 오류가 났는지 대화 기록에서 볼 수 있어요.

• 자세한 기록: claude --debug-file /tmp/claude.log로 켜면 훅이 몇 번 코드로 끝났는지까지 남습니다. 위 실험의 판정도 이 기록으로 했어요.


마지막으로 보안 이야기입니다.

명령 훅은 내 계정 권한 그대로 실행됩니다. 파일을 지우는 명령을 적으면 정말 지워져요.


• 인터넷에서 본 훅을 붙여넣기 전에 한 줄씩 읽고, 연습 폴더에서 먼저 시험하세요.

• 남이 만든 저장소에는 .claude/settings.json에 훅이 들어 있을 수 있습니다. 평소처럼 대화하며 쓰는 화면에서는 그 폴더를 믿는다고 확인하기 전까지 실행되지 않지만, claude -p처럼 한 번에 실행하는 방식은 그 확인을 건너뜁니다.

• 모든 훅을 잠시 끄고 싶다면 설정에 "disableAllHooks": true를 넣습니다. 훅 하나만 끄는 스위치는 없어서, 하나만 빼려면 지워야 해요.



6. 자주 묻는 질문 - 이런 건 어떨까요?


Q. 훅 설정을 Claude에게 만들어 달라고 해도 되나요?

네, 공식 문서도 원하는 동작을 말로 설명해 Claude에게 맡기는 방법을 안내합니다.

다만 실행되는 건 내 권한의 명령이니, 만들어 준 내용은 꼭 읽어 보고 적용하세요.


Q. 훅은 많을수록 좋은가요?

아니요. 공식 모범 사례는 강제하는 규칙을 적게 유지하라고 권합니다.

규칙마다 엉뚱하게 걸리는 순간이 생기고, 누군가는 계속 관리해야 하기 때문이에요. 취향에 가까운 것은 CLAUDE.md에 남겨 두세요.


Q. 설정을 고쳤는데 바로 적용되나요?

클로드 코드를 켜 둔 채로 설정 파일을 고치면 보통 자동으로 반영됩니다.

몇 초가 지나도 /hooks에 보이지 않으면 클로드 코드를 다시 시작해 보세요.


Q. Edit|Write 훅이면 파일 변경을 전부 잡을 수 있나요?

그렇지 않습니다. 4-1의 실험처럼 Claude는 셸 명령으로도 파일을 바꿀 수 있어요.

공식 문서는 모든 변경을 확인해야 한다면 Stop 훅으로 답이 끝날 때마다 한 번 더 살펴보는 방법 등을 함께 쓰라고 안내합니다.


공식 문서에서 더 확인하고 싶다면


• 훅으로 작업 자동화하기(입문 가이드): https://code.claude.com/docs/en/hooks-guide

• 훅 레퍼런스(전체 이벤트와 보안 주의): https://code.claude.com/docs/en/hooks

• 클로드 코드 모범 사례: https://code.claude.com/docs/en/best-practices
