# 동탄 중심 부동산 시장 모니터링 시스템 PRD

2026-10-23 작성 · 2026-10-26 개정 (허점 3건 보완) · @MATT

> 개정 요약: ① 소표본 지역은 "판단 보류" 규칙 추가(F-09, 7절) ② 첫 수집 호출 수 추정을 약 500회로 정정(6절) ③ PC 꺼짐 시 대시보드 접속 불가와 Streamlit 노출 범위를 리스크·완료 기준에 추가(9·11·12절)

## 1. 개요

집 Windows PC에서 6개 지역의 5년치 아파트 매매 실거래가를 자동으로 모아, 규칙 기반으로 시장 흐름을 판정하고 PC·폰 대시보드와 주간·월간 메일 보고서로 보여주는 개인용 무료 시스템이다.

배경: 투자 판단과 부동산 공부를 위해, 동탄을 중심으로 주변 지역 시장 흐름을 꾸준히 추적할 도구가 필요하다. 기존에 GPT와 Apps Script로 시도했으나 함수가 길어지며 흐름 파악이 어려웠고, 이번에는 Claude Code로 처음부터 다시 만든다.

개발자는 코딩 비전공자이며, Claude Code가 코드를 작성하고 사용자는 방향 결정과 결과 확인을 맡는다.

## 2. 목표와 비목표

v1의 성공 기준은 "월 0원으로, 손대지 않아도 매주 6개 지역의 거래 흐름을 신뢰할 수 있는 숫자로 받아보는 것"이다.

**목표**

- 6개 지역 × 5년 이상 실거래 데이터를 빠짐없이, 중복 없이 누적
- 화성시 구 신설(2026-02-01) 전후 데이터를 이어서 하나의 추이로 비교
- 지역별 상승/보합/하락 판정을 근거·반대 근거·신뢰도와 함께 제공하되, 표본이 부족하면 억지로 판정하지 않고 "판단 보류"로 표시
- PC와 폰 어디서든 "핵심 숫자 먼저, 세부는 나중" 구조의 대시보드 확인, 주간·월간 보고서를 메일로 수신
- 설치 후 자동 실행, 서울 등 관심지역은 설정에 등록만 하면 수집·분석·화면에 자동 반영

**비목표 (v1에서 하지 않음)**

- 투자 추천이나 매수·매도 시점 제시
- 단지 단위 분석, 전월세, 금리·공급·정책·뉴스 데이터
- 일일 보고서, AI(유료 API) 해석
- 다른 사람과의 공유·다중 사용자 기능
- PC가 꺼져 있을 때의 대시보드 접속 (메일 보고서가 그 역할을 대신함)

## 6. 데이터 요구사항

원천은 공공데이터포털의 "국토교통부_아파트 매매 실거래가 자료" 하나이며, 지역코드(5자리) + 계약년월로 조회한다. 개발계정 일일 한도는 10,000회다.

**수집 기간: 5년 유지 (6개월은 대안으로만 보류)**

| 상황 | 예상 API 호출 | 일일 한도 대비 |
| --- | --- | --- |
| 첫 수집, 6개 지역 × 5년 | 약 500회 이내 (6곳×60개월=360회 + 개편 전 화성시 조회 60회 + 페이지 추가분 여유) | 5% 수준 |
| 이후 주간 갱신 (6곳 × 최근 3개월 재조회) | 약 20회 | 0.2% 수준 |
| 서울 25개 구 추가 시 첫 수집 | 약 1,500회 추가 (25구×60개월) | 하루 안에 가능 |

호출 수는 월 단위 조회에서 결과가 한 페이지를 넘는 달이 있으면 늘어난다. 정확한 수치는 F-02의 사전 계산이 실제 총 건수 기준으로 보여주며, 위 표는 계획용 추정이다.

트래픽은 5년치에도 여유가 크다. Claude 사용량은 데이터 양이 아니라 Claude Code가 읽는 양에 좌우되므로, 원본 데이터 대신 건수 요약표만 확인하게 하는 규칙으로 관리한다. 실제 수집에서 한도나 속도 문제가 확인되면 그때 최근 6개월(현재 시세 추적용)로 줄인다.

신설 구 코드는 PRD 작성 시점의 가정이며, 1단계 실조회에서 확정한다.

**화성시 개편 처리**

- 계약일 기준으로 2026-01-31 이전은 개편 전 코드, 2026-02-01 이후는 신설 코드 체계를 적용한다.
- 원본에 기록된 지역코드는 바꾸지 않고, 분석용 "분석구역" 칸을 따로 둔다.
- 법정동 → 구 대응표는 신설 코드로 조회된 거래에서 추출하고, 사용자 확인 후 적용한다. 대응표에 없는 법정동은 "미배정"으로 남긴다.
- API가 과거 거래를 옛 코드로 주는지 신설 코드로 주는지는 1단계에서 실제 조회로 먼저 검증한다.

**정제 규칙**

- 해제(취소) 거래: 원본은 보존, 분석에서는 제외
- 직거래: 거래량에는 포함, 가격 통계에서는 제외
- 가격: 평균 대신 중위값, 전용 84㎡ 근접 구간 우선 + ㎡당 가격 병행 (근접 구간 범위는 분석 단계에서 실제 거래 분포를 보고 확정)
- 신고 지연: 최근 4주(주간)·최근 1개월 거래는 "잠정" 표시

## 7. 분석 규칙 (초안)

아래 기준값은 출발점이며, 5년치 데이터를 과거 시점에 적용해 실제 흐름과 맞는지 확인한 뒤 4단계에서 확정한다. 모든 기준값은 설정 파일에서 바꿀 수 있게 한다.

| 항목 | 초안 기준 |
| --- | --- |
| 비교 구간 | 최근 3개월 vs 직전 3개월, 최근 3개월 vs 전년 동기 |
| 표본 최소 기준 | 비교하는 두 구간 각각의 가격 통계 대상 거래가 N건 미만이면 "판단 보류" (N 초안값 10건, 4단계에서 지역별 실제 거래 규모를 보고 확정) |
| 상승/하락 | 표본 최소 기준을 넘고, 가격 중위값 ±2% 이상 변화 + 거래량이 같은 방향 |
| 보합 | 표본 최소 기준을 넘고, 변화가 ±2% 이내이거나 가격·거래량 방향이 엇갈림 |
| 판단 보류 | 표본 최소 기준 미달. 방향 표시 없이 "거래가 적어 판단 보류(최근 N건)"로 표기하고, 참고용 숫자만 보여줌 |
| 신뢰도 | 비교 구간 거래 건수로 높음/보통/낮음 구분 (판단 보류는 신뢰도 대상 아님) |
| 반대 근거 | 판정과 반대 방향을 가리키는 지표를 자동 표시 |
| 이상 신호 | 1개월만 튀면 초기 징후, 3개월 연속이면 확인된 변화 |

판정은 "시장 결론"이 아니라 "거래 데이터가 보여주는 신호"로 표기한다. 금리·정책 같은 외부 요인은 v1에서 반영하지 않는다. 결론 한 줄과 보고서 요약에서는 판단 보류 지역을 "보합"에 섞지 않고 따로 센다(예: "2곳 상승 신호, 3곳 보합, 1곳 판단 보류").

## 8. 출력 요구사항

대시보드와 보고서 모두 두괄식이다. 첫인상은 결론 한 줄과 핵심 숫자로 단순하게 시작하고, 아래로 내려가거나 누를수록 세부 정보가 나온다.

**대시보드**

1. **결론 한 줄**: 예) "이번 달 6개 지역 중 2곳 상승 신호, 3곳 보합, 1곳 판단 보류"
2. **핵심 숫자 카드**: 지역별 판정(또는 판단 보류), 최근 거래량, 가격 중위값의 전월·전년 대비 변화(%)
3. **전체 추이**: 등록된 전체 지역의 월별 거래량 비교 차트
4. **지역 상세**: 지역 선택 → 가격 중위값·㎡당 가격 추이, 화성시 개편 시점, 잠정 구간 표시
5. **근거와 원자료**: 판정 근거·반대 근거·신뢰도, 거래 목록

화면 원칙: 숫자는 크게, 설명은 짧게, 색은 상승·하락 구분에만 쓴다. 지역이 늘어나면 시·도 단위로 묶어 접고 펼친다. PC와 폰 모두 같은 순서로 보인다.

| 주간 | 매주 월요일 아침 | 직전 주까지 반영분 | 지역별 신규 거래 수, 판정 변화, 이상 신호 (최근 4주는 잠정) |
| 월간 | 매월 말일 | 지난달 | 지역별 판정·근거·반대 근거·신뢰도, 전월·전년 대비 변화 |

보고서도 같은 순서를 따른다: 맨 위 결론 한 줄과 핵심 숫자, 그 아래 지역별 표, 마지막에 근거와 잠정 안내. 세부 항목과 문구는 실제 데이터를 본 뒤 7단계에서 확정한다.

## 10. 기술 구성

| 백업 | Git | 기능 완성 시점마다 저장, 되돌리기 가능 |

## 11. 로드맵과 완료 기준

한 단계가 완료 기준을 통과해야 다음 단계로 넘어가며, Claude Code 세션 하나에 한 단계만 진행한다.

1. **준비**: Claude Code 설치, 작업 폴더·가상환경·.env·Git, CLAUDE.md 배치 → Claude Code가 폴더에서 정상 응답
2. **수집 시험**: 동탄구 몇 개월 + 개편 전후 코드 검증 → 개편 전 데이터가 어느 코드로 나오는지 확정, 건수가 상식적
3. **전체 수집**: 6곳 × 5년 + 법정동 대응표 → 월별·지역별 건수 요약표에 빈 달·급변 없음, 미배정 법정동 확인 완료, 실제 호출 수를 기록해 6절 추정과 비교
4. **분석**: 정제 + 판정 규칙 → 과거 시점에 적용한 판정이 납득됨, 기준값과 표본 최소 기준(N) 확정, 거래가 적은 지역(예: 오산시)에서 판단 보류가 과하지도 모자라지도 않은지 확인
5. **대시보드**: 1층·2층 화면 → PC 브라우저에서 확인, 판단 보류 카드 표시 확인
6. **폰 연결**: Tailscale → 집 밖에서 폰으로 대시보드 열림, 같은 와이파이의 Tailscale 미등록 기기에서는 열리지 않음 확인
7. **보고서**: 주간·월간 메일 → 테스트 메일 수신, 내용 확인
8. **자동 실행**: 작업 스케줄러 → 절전 해제·재부팅 후 자동 수행 확인, 한 주 동안 손대지 않고 주간 보고서 수신

## 12. 리스크와 대응

가장 큰 리스크는 화성시 개편 전 데이터가 잘못 이어 붙어, 동탄·병점의 과거 추이가 조용히 왜곡되는 것이다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 개편 전 데이터 배정 오류 | 동탄·병점 5년 추이 왜곡 | 1단계 실조회 검증, 대응표 사용자 확인, 미배정 별도 표시 |
| 신고 지연 | 최근 거래량이 실제보다 적게 보여 하락 오판 | 잠정 표시, 월간은 말일 발송 |
| 소표본 지역의 판정 흔들림 | 거래가 적은 지역에서 중위값 몇 건에 상승/하락이 뒤바뀜 | 표본 최소 기준 미달 시 "판단 보류", 기준값은 4단계에서 지역별 거래 규모로 확정 |
| PC 꺼짐·재부팅 | 보고서 누락 | 놓친 작업 자동 실행, 실행 로그 확인 |
| PC 꺼짐·절전 시 대시보드 접속 불가 | 밖에서 폰으로 확인 불가 | 전원 설정에서 절전 해제, 8단계 점검 항목에 포함, 필수 정보는 메일 보고서로 확보. 상시 가용은 v1 비목표 |
| Streamlit 노출 범위 | 같은 네트워크의 다른 기기에서 대시보드 열람 | Tailscale 주소에만 바인딩, 6단계에서 외부 기기 접속 차단 확인 |
| 공공 API 사양·한도 변경 | 수집 실패 | 실패 로그·재시도, 건수 검증으로 조기 발견 |
| 관심지역 급증(서울 등) | 첫 수집 호출 증가, 화면 과밀 | 신규 지역만 과거 수집·나눠 실행, 시·도 단위 묶음 표시 |
| 5년 수집 부담 | 첫 수집 지연, 사용량 증가 | 문제 확인 시 최근 6개월로 축소 |
| 규칙 판정의 단순함 | 외부 요인 반영 못 함 | "데이터 신호"로 표기, 다음 버전에서 금리·정책 추가 검토 |
| 바이브코딩 누적 복잡도 | 흐름 파악 어려움, 중복 코드 | 역할별 파일 분리, 흐름 요약표, 단계마다 정리 |

- [ ] 판정 기준값, 표본 최소 기준(N), 84㎡ 근접 구간 범위 확정 (4단계, 데이터 확인 후)

- [ ] 대시보드 디자인 세부 (5단계)

**용어**

| 용어 | 뜻 |
| --- | --- |
| Claude Code | Claude가 내 PC 폴더 안에서 파일을 만들고 코드를 실행·수정해주는 도구 |
| CLAUDE.md | Claude Code가 작업 폴더에서 매번 읽는 안내문 파일 |
| SQLite | 파일 하나로 된 가벼운 데이터 저장소 |
| Streamlit | Python 데이터를 웹 화면 차트로 보여주는 무료 도구 |
| Tailscale | 내 기기끼리만 연결되는 개인 전용 통로, 폰에서 집 PC 접속용 |
| 작업 스케줄러 | 정해진 시각에 프로그램을 자동 실행하는 Windows 기능 |
| .env | 인증키 같은 비밀 값을 코드와 분리해 보관하는 파일 |
| 중위값 | 값을 줄 세웠을 때 한가운데 값, 초고가 몇 건에 덜 흔들림 |
| 바인딩 | 프로그램이 어느 네트워크 주소로 접속을 받을지 정하는 설정 |
| 표본 | 판정에 쓰이는 거래 건수. 적을수록 숫자가 우연에 흔들림 |
| Git | 파일 변경 기록을 저장해 이전 상태로 되돌릴 수 있게 하는 도구 |
